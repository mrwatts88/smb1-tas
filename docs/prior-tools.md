# Prior bots and search tools for SMB1 (P0.8 survey, 2026-08-21)

Sources read: TASVideos topics 8431 (Lua brute-force bots), 14693 (Bobo_the_King's brute-force
script), submission #5862S (MrWint warpless) and its thread 20204, #5975S, GameResources/NES/SuperMarioBros,
speedrun.com threads 75044 ("The Limit of 1-2"), 0jnl2, beov8; GitHub: MrWint/smb-opt, silverslither/
SMB-TASTools, ddugovic/tasbot (Tom 7's learnfun/playfun), pellsson/smb, scottyw/smb-tas, kobolt/lazyboNES.

## 1. MrWint/smb-opt — the only exhaustive-search tool for SMB1 (2017–2018)
- **What.** Rust (2018 nightly: `associated_type_defaults`, `fixed_size_array`), ~10.5k lines,
  cloned to `third_party/smb-opt` (commit daa44287, gitignored). A hand-extracted **player-physics
  model** from doppelganger's disassembly: state = x/y (with subpixels), x/y speed (with the
  $0705-style fractions), player state, moving/facing dir, vertical forces, x_spd_abs, running
  speed/timer, collision bits, crouch, jump/swim timer, optional screen-edge position and
  side-collision timer, coins/power-up flags, parity — packed into **10–12 bytes**
  (`src/state.rs`). Level geometry from per-world **block buffers** (`src/blockbuffer/world*.rs`,
  generated by `bbconvert.py`). **Enemies are ignored** entirely. NTSC and PAL platforms.
- **Search.** IDA* (`src/ida.rs`) with a per-state input set pruned by game logic (`valid_next_inputs`:
  B only with the moving direction, L+R only on the ground, A only when a jump can start or continue,
  Down/Up only where they matter) and a **VecHashMap** store of compressed states. Heuristics
  (`src/heuristics/`): `XPosHeuristic` precomputes, over the x-physics substate (x_spd, x_spd_abs,
  moving/facing dir, on-ground, running_speed), the exact maximum/minimum x gain after n steps
  by BFS on that substate — an admissible, tight "steps until x ≥ X" bound (this is the sound
  acceleration bound P2.1a lacked); `ypos.rs`/`BoundsHeuristic` do the same for y and for a box.
- **Cases solved** (`src/case/*.rs`, each with the optimal input sequence in a comment): 1-1
  speed-up (59 frames), start→pipe (368), bonus room speed-up (88) and exit with 11/13 coins (111),
  third room speed-up to the stairs (174), **"stairs to half flagpole glitch" (59)** from a
  hand-picked stairs state (x 0xbd510, speed 0x2848), 1-2 speed-up/mushroom/"exit pipe to half
  FPG", 1-3/2-3 floor clips + full FPG, 1-4 speed-up/fire flower, 2-1 scroll/clip variants (x-loss
  tables), 2-2, 3-1, 3-3, 4-4 speed-up + **wall-clip shortcut (52)** (the 21-frame 4-4 save in
  #5862/#5975), 6-2 vine, 7-1, 8-2, 8-4 part 2/3/4 speed-ups and pipe-clip entries.
- **Limits (author).** "~1000× faster than full emulation"; "hard to fit more than a billion states
  into memory" → heuristic pruning; cannot solve whole levels; segments are chained by hand
  (each segment's start state is the previous solution's end), so chained results are not
  globally optimal; enemies/RNG/scroll-dependent spawns are outside the model.
- **For us.** (a) A validated-by-use fast physics model: build it (rustup nightly in the `smb1`
  toolbox) and differential-test it against QuickNES on the WR path → P1.2-lite. (b) The
  XPos/YPos heuristic tables are the sound tight bounds for P2.1b/c. (c) His 1-1 third-room
  segments (174 + 59 frames from a chosen handoff) are the state of the art to beat: our search
  should run the whole room from the fixed entry (F47) with the FPG goal, which his tool never did
  as one search.

## 2. Bobo_the_King's brute-force script (TASVideos 14693, FCEUX 2011 / BizHawk 2015)
Lua; user-specified button press/release events with time windows and a RAM objective; runs
"all timings within the ranges", e.g. an SMB wall-jump example minimising Mario's Y ($CE) over 780
iterations × 90 frames. Not a state-space search; no dedup; no SMB results beyond demos.

## 3. TASVideos topic 8431 (2009, Lua brute force in general)
Random-input vs exhaustive per-frame enumeration; consensus "the Sun will explode first";
branch-and-bound bot for Super Punch-Out (ntclark); no SMB bot.

## 4. Tom 7's learnfun/playfun (ddugovic/tasbot fork, FCEUX)
Learns an objective from RAM traces of human play and extends play by search over input motifs;
"more or less works for easy games like Super Mario Bros", 5 minutes per second of play; not an
exact or exhaustive search.

## 5. silverslither/SMB-TASTools (Lua, FCEUX/BizHawk)
Productivity script: preset subpixel manipulator, ground-acceleration lookup, **subspeed searcher**,
airborne-state seeker, framerule remainder display. Human-in-the-loop; no state search.

## 6. Pellsson's practice ROM (pellsson/smb, threecreepio forks)
ROM hack for practice (framerule select, savestates, displays). Not a search tool; useful as a
reference for displays only.

## 7. Other
scottyw/smb-tas: a manual BizHawk TAS project (movie, no tooling). kobolt/lazyboNES: a terminal
NES emulator that plays .fm2 (not a search tool). Community practice: "wall clipping is basically
a tedious brute-force for me" (redatchyon2098, 2021) — i.e. manual.

## Conclusions for the ledger
- Nobody has run a full-state or whole-level exhaustive search on SMB1; the only exhaustive
  searches are MrWint's segment searches in a player-only model (enemies ignored) with hand
  handoffs. The community's "1 frame short" claims for 1-1 and 1-2 rest on manual optimisation
  plus those segments — no proof artifact (consistent with F35).
- speedrun.com 75044 (Maru370, 2024): a "perfect 1-2" is 3 frames faster than HappyLee's and "5
  frames away from the next framerule"; zdoroviy_antony saved 7 more subpixels, "not enough to
  save the frame". → H22's deficit is 5 on the best-known 1-2, not 8.
