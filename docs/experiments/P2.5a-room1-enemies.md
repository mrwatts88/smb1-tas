# P2.5a — 1-1 room 1 enemy model (H29 groundwork)

Goal: an exact, data-driven model of the enemies Mario meets in 1-1 room 1 (control → the warp pipe at
page 3 col 9, x 912), good enough to search the room with bounces (H29). Session 5 (2026-08-22) delivered the
rule set, read from the disassembly and validated against the WR dump by a reference simulation; the port into
the smb-opt search model (Rust) + differential test is the next step.

## Inventory (`tools/area_data.py E_GroundArea6`, `L_GroundArea6`)
Enemy objects before the warp pipe: goomba **A** page 1 col 6 (x 352), goomba **B** page 2 col 8 (x 640), a goomba
**pair** id $37 at page 3 col 6 (data column x 864; the group's actual position is the screen edge at spawn, see
below). The green koopa (page 6 col 11) and the other groups are past the pipe and cannot spawn before Mario
enters it (spawn needs ScreenLeft ≥ x − 303; at pipe entry ScreenLeft = 786). Solids at the goomba side-check
row: the pipes at x [448,480), [608,640), [736,768), [912,944); the ground is continuous (no holes before x 1104).
The WR stomps A (row 323) and the pair's first goomba (row 517) — two forced bounces in a 368-frame segment
that still equals the enemy-free optimum (F63).

## Rules (smbdis.asm; all verified by `tools/room1_enemy_sim.py`)
Frame order (`GameCoreRoutine`/`GameEngine`): player movement → `ScrollHandler` → enemy slots 0..5 in order
(`EnemiesAndLoopsCore`: a free slot tries to spawn, a live one runs) → player graphics/relative position.
- **Scroll** (`ScrollHandler`): amount = `Player_X_Scroll` (Mario's x delta this frame) when the *previous*
  frame's `Player_Pos_ForScroll` (Mario x − ScreenLeft) ≥ $50 and `SideCollisionTimer` = 0 and the amount > 0;
  minus 1 when the amount ≥ 2 and the position < $70. ScreenRight = ScreenLeft + 255. 0 mismatches, 369 frames.
- **Spawn** (`ProcessEnemyData`, `CheckRightBounds`): for each free slot 0..4 (slot 5 only takes id $2E) on
  frames with `AreaParserTaskNum & 7 ≠ 7`, the next enemy object (x = column<<4 on `EnemyObjectPageLoc`) loads
  iff ScreenRight ≤ x ≤ (ScreenRight + 48) & ~15, i.e. **ScreenLeft + 303 ≥ x** (16-bit); an object already
  left of ScreenRight is consumed unloaded; the next-page bit and the page-skip row $0F go through
  `EnemyObjectPageSel` (so a re-examined object is not re-paged). A single enemy lands in the *current* slot
  (x = column<<4, y = row<<4 + 8); a **group** ($37–$3E, `HandleGroupEnemies`) lands in the first free slots
  with **x = ScreenRight at that frame** (+24 each), y = $B0 (+8) ($70 with d1) — so the pair's position is
  path-dependent (816 in the WR; 817 when the spawn frame's scroll differs, see control 2). Goomba init
  (`InitGoomba`): X speed $F8, moving dir 2 (left), bbox ctrl 9, masked offscreen bit 1 until recomputed;
  **`Enemy_X_MoveForce` and `Enemy_CollisionBits` are not initialised** — the half-pixel phase is inherited from
  the slot's previous occupant (A: force 0 → moves on the next frame; B reuses slot 0 with force 128).
  A freshly spawned enemy does not run its own routine in the spawn frame (the spawn replaced it), but a
  group member placed in a *later* slot does (the WR's second pair goomba moved in its spawn frame).
- **Per live goomba per frame** (`RunNormalEnemies`): (1) offscreen bits (`GetXOffscreenBits`, right edge first:
  beyond ScreenRight → $FF, within 56 px left of it → $7F>>k; left edge similarly) and
  `EnemyOffscrBitsMasked` = bits & $48 (or $44 when at/left of ScreenLeft) — an enemy strictly beyond
  ScreenRight is masked: no collisions, box = $FF; (2) bounding box from the screen-relative position:
  x+3…x+13, y+14…y+20 (`BoundBoxCtrlData[9]`); (3) `EnemyToBGCollisionDet`: ground under (x+8, y+24) → `DoEnemySideCheck`:
  the block at (x+0 if moving left, x+16 if right; y+20) solid → `EnemyTurnAround` (speed negated, dir ^= 3),
  checked *before* the move; (4) `EnemiesCollision` on odd `FrameCounter` only: against every lower slot with a
  box, inclusive overlap → unless the pair bit `Enemy_CollisionBits[lower] & (0x80 >> upper)` is already set,
  set it and turn *both* around (a flattened state-4 goomba counts: the WR's second pair goomba reverses off the
  flattened first one at row 544); no overlap clears the bit; (5) `PlayerEnemyCollision` on even `FrameCounter`
  (F59); a stomp sets state 4 and `EnemyIntervalTimer` = 16 (speed is *not* zeroed — F59 corrected);
  (6) movement (`MoveObjectHorizontally`): force += $80; x += (−1 or 0) + carry for speed −8, (0 or 1) for +8 —
  0.5 px/frame with the phase in bit 7 of the force; state 4 does not move and is **erased when its interval
  timer reaches 14** (`ChkKillGoomba`); interval timers tick on the frames where `IntervalTimerControl` wraps to
  20 (every 21 frames), so a flattened goomba lasts 22–42 frames; (7) `OffscreenBoundsCheck`: erased when
  x < ScreenLeft − 73 or x ≥ ScreenRight + 72 (+1 when ScreenLeft ≥ 73).

## Validation: `tools/room1_enemy_sim.py` (reference simulation vs the WR dump)
Command: `python3 tools/room1_enemy_sim.py` (defaults `data/wr/fceux_wr.ram` rows 197–565 = control → pipe entry).
The sim takes Mario's position/y-speed, the scroll, `FrameCounter`, `IntervalTimerControl`, `AreaParserTaskNum` and
`GameEngineSubroutine` from the dump, simulates the enemy slots and the enemy-data parser, and compares every frame:
flag, id, state, x (16-bit), X speed, move force, moving dir, interval timer, masked bits for slots 0–4, plus
`EnemyDataOffset`/`EnemyObjectPageLoc`/`EnemyObjectPageSel`. Result: **0 mismatching rows over 369 frames**, predicted
stomp rows {323, 517} = the dump's `StompTimer` rows, scroll law 0 mismatches. Event trace: spawn A 352 → stomp 323 →
spawn B 640 → B turns at the pipe (row 381, x 639) → pair spawns 816/840 (row 467) → stomp 517 → B turns at the next pipe
(542, x 720) → pair #2 reverses off the flattened #1 (544) → B erased offscreen (557).
Negative controls (the comparison bites): pipe edge +1 px → 178 mismatching rows; spawn bound +32 instead of +48 →
303 rows (A is never stomped, B takes slot 1, the pair spawns at 817 — the path-dependence the model must carry);
enemy–enemy collision off → 243 rows.

## Implications for the Rust model (next step: port + difftest)
- State per enemy (A, B, pair#1, pair#2): status ∈ {unspawned, alive, flattened, gone}; for alive/flattened:
  slot (0–2), x (or spawn frame + the deterministic walk), moving dir, move-force phase bit, interval timer (flattened),
  collision bits (player d0, pair bit). Positions are *not* frame functions any more: the spawn frame depends on
  the scroll (Mario's path) and the pair's x on ScreenRight at its spawn frame.
- The player model must track the scroll (`WithScrollPos`: `left_screen_edge_pos`, `side_collision_timer`), and
  MrWint's `scroll_handler` uses the *current* frame's x for the $50/$70 test where the game uses the previous
  frame's `Player_Pos_ForScroll` — to be checked by the difftest (it only matters when the thresholds are crossed).
- `AreaParserTaskNum & 7 == 7` blocks spawns for one frame; it derives from `ScrollThirtyTwo` (scroll history),
  so the model needs ScrollThirtyTwo (5 bits) + the task counter, or a validated approximation.
- Only goombas are needed before the pipe; the koopa and the row-$70 groups are beyond it.
