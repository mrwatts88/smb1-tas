# P0.4 — Slack table of the WR (2026-08-21)

## Goal / acceptance
`tools/slack_table.py` prints, per level of #1715M: frames, framerule phase at the quantized
event, frames-to-previous-framerule (deficit) and frames-of-slack, lag frames, RNG at entry,
ending coast; numbers land in facts + STATUS Key numbers.

## Command

```
python3 tools/slack_table.py data/wr/fceux_wr.ram "data/wr/happylee-supermariobros,warped.fm2"
```
(`data/wr/fceux_wr.ram` = full RAM per frame from P0.3; row i = fm2 frame i−1.)

## Mechanism (from `data/disasm/smbdis.asm`, verified against the dump)
1. **Interval timers.** `DecTimers` (NMI, before the game logic) decrements `IntervalTimerControl`
   ($077F) every frame; when it underflows it is reset to 20 and the *interval* timers
   ($0796–$07A3) are decremented — i.e. every 21 frames. Frame timers ($0780–$0795) tick every frame.
2. **Flagpole levels.** `StarFlagTaskControl` ($0746): 1 `GameTimerFireworks` (fireworks count
   from the timer's last digit), 2 `AwardGameTimerPoints` (**1 timer unit per frame**, 50 pts
   each), 3 `RaiseFlagSetoffFWorks` (raise the castle flag 1 px/frame to Y<$72, fire fireworks),
   then `DrawFlagSetTimer` sets the star-flag object's `EnemyIntervalTimer` ($0796+slot) = 6 and
   task 4 `DelayToAreaEnd` waits for that timer **and** `EventMusicBuffer` ($07B1) = 0; task 5 →
   `PlayerEndLevel` → `NextArea` → `ChgAreaMode` (OperMode_Task = 0) the same frame.
   With post-frame ITC = v on the frame T_set where the timer is set, it expires at
   T_set + (v+1) + 5×21. **slack = v** (T_set may be later at no cost), **deficit = 21 − v**
   (T_set must be this much earlier to save a framerule). Prediction = observation in all 5 flag
   levels; music never binds (it ends before the timer).
3. **Area loads.** Every load runs `ScreenRoutines`; main-level entries (AltEntranceControl = 0)
   show the "WORLD x-y" card via `ScreenTimer` ($07A0, interval timer). Trace of a load L:
   L+1 task reset, L+2 = the load's lag frame (task 1, InitScreen), screen-routine tasks 0–6 one
   per frame, **ScreenTimer = 7 written on L+8** with post-frame ITC = w, card ends after
   (w+1) + 6×21 frames (task 7), then 12 column-render frames + 3 palette tasks + task 2 + task 3
   + 2 entrance frames = 19 → **control = L + 154 + w**, w = (u − 7) mod 21 with u = ITC at L
   (holds exactly for all six main entries; 1-1: u=7 → w=0 → 154; flag levels: u=19 → w=12 → 166).
   **Pipe levels (1-2, 4-2)** end with `VerticalPipeEntry` + `ChangeAreaTimer` ($06DE = 48, a
   frame timer) — no quantization at the pipe — so their framerule is set at the next load:
   **slack = w, deficit = 21 − w**.
4. **Sub-area loads** (AltEntranceControl ≠ 0: 1-1 bonus room in/out, 4-2 wrong-warp re-entry,
   the four 8-4 rooms) skip the card: no `ScreenTimer` wait, **not quantized** (control at
   load + 43, or +122 after a vertical pipe exit). The 1-2/4-2 pipe-intro areas take exactly 499
   rows and are auto-walk (no control).
5. **8-4** ends on the axe (`OperMode` → 2): unquantized, every frame counts 1:1.

## Interpretation
- **1-1 is exactly 1 frame from the next framerule** (−21 frames). That frame must come out of
  T_set: the flagpole glitch 1 frame earlier, or the countdown (1 frame per timer unit; the
  timer ticks every 24 control frames, so one unit less on the clock at the grab also counts, H4),
  or the castle walk / flag raise (fixed by geometry — levers to be listed in P0.5).
- Next: 1-2 (8 frames: the warp pipe entered 8 frames earlier), 4-1 (9), 8-3 (10), 4-2 (13);
  8-1 (18) and 8-2 (19) are nearly a full framerule. (An earlier draft said 1-2 = 1 and 4-2 = 6
  from the load-row phase u; the correct phase is w at load+8 — see item 3.)
- 8-4 is the only level where partial gains count; Track A's order: **1-1 → 8-4 → 1-2 → 4-1 → 8-3 → 4-2**.
- Saving a framerule shifts all later levels by exactly 21 frames = one ITC period, so later
  framerule phases are unchanged, but FrameCounter/RNG phases change (enemy patterns differ; a
  later level may need re-optimization — H9).
- None of the lag frames is in-level; all are load frames, so H2 (remove lag) is about loads only
  (P0.5: can a load frame be avoided at all?).
