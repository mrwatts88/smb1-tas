# P1.2-lite — MrWint's smb-opt player model: build and validation against QuickNES

**Setup.** `third_party/smb-opt` (commit daa44287) built with rustup `nightly-2018-06-01`
(rustc 1.28.0-nightly 2018-05-31; installed user-level with `--no-modify-path`, binaries in
`~/.cargo/bin`; `cargo build --release` takes 3.5 min incl. the crates.io index). Added a
`trace11pipe` mode to `src/main.rs` (and made `w11_pipe_start` public): runs the 1-1 third-room
model from its entry state with NES-order input bytes and prints x/y/speeds/state per step;
optional `STEP:yspd=VALUE` overrides. Reference: QuickNES WR trace rows 1047–1291
(`tools/ram_trace.py` fields X/page/$0705, Y/high/$0433, $57, $9F, $1D).

**Commands.**
```
sh rustup-init.sh -y --no-modify-path --default-toolchain nightly-2018-06-01 --profile minimal
cd third_party/smb-opt && ~/.cargo/bin/cargo build --release
./target/release/smb-opt trace11pipe ../../data/wr/wr_inputs.bin 1048 245 [66:yspd=-1024]
```
(record 1048 = QuickNES frame 1046, the first control frame; comparison script inline in the log.)

**Results.**
- Without enemies the model matches the core **exactly** (x pixel, y pixel, 8.8 x speed incl.
  the $0705 fraction, 8.8 y speed incl. $0433) for rows 1047–1111 (64 frames: L+R facing trick,
  airborne doubled acceleration, landing, ground run to 40).
- Row 1112: the core's Mario gets Y speed −4 with no input — a goomba stomp bounce
  (`EnemyStomped`: `lda #$fc; sta Player_Y_Speed`). The model ignores enemies → divergence.
- Injecting the bounce (`66:yspd=-1024`, i.e. y_spd = −4.0 after step 65, state JUMPING) the
  model matches every remaining row and ends with `StateChangeFlag(198, 9)` at step 239 =
  QuickNES row 1286, X 3161, Y 164 — exactly the WR's flagpole-glitch grab. Only the bounce
  frame itself differs (display of the injected value).

**Conclusion.** smb-opt's player physics + block-buffer collision is frame- and subpixel-exact
on the WR's 1-1 third room (stairs, pole base embed, FPG trigger included); the only missing
mechanic on this path is enemy interaction (the goomba bounce, which the WR uses). For a
complete 1-1 third-room search the model needs the two goombas (deterministic walkers spawned
by screen position) or a hybrid (model for bounds, core for verification). The XPos heuristic
machinery can be reused as the sound x bound.

## Random-input differential test (session 4, 2026-08-21) — `tools/model_difftest.py`
**Setup.** Input files = the WR's records up to a root record, then random A/B/L/R records (per-frame
button probabilities) or the WR's own records with K random frames replaced (`--mutate K`, FPG-dense).
Core: `build/harness … --input-skip 2 --ram` (RAM after every frame); model: `smb-opt trace11pipe`
from `w11_pipe_start` with the goomba bounce injected at step 66 (F53). Compared per frame: X (page:pixel),
x subpixel ($0400), x speed ($57) + fraction ($0705), Y (high:pixel), y speed ($9F) + fraction ($0433),
player state ($1D); at a grab: the frame, Y, and FPG (model y ≥ 0x1a200 vs core GES 5 in the grab frame —
the core goes 4 → 5 in the same frame on a glitch grab, F55).

**First run (model as cloned, `NoRunningTimer`): 53 of 200 trials diverged.** Classes: (1) `XSPD model 24
core 40` on the first frame without B: the game keeps the run cap for 10 frames after B is released
(`RunningTimer` $0783, `X_Physics`); MrWint's 1-1 cases are configured with `NoRunningTimer`. (2) the
model jumped on a *held* A (`STATE model 1 core 0`, `YSPD model −5 core 0`): `CheckForJumping` requires A
not pressed on the previous frame (`PreviousA_B_Buttons` $0D, saved at `SaveAB` every frame); the model had
no such state. The two other classes (airborne speed 26 vs 24; grab Y 160 vs 156) were consequences.

**Fixes (in `tools/smb-opt-modes.patch`).** `State.a_held` (1 bit, set from the raw A input at the end of
`run_step`, gates the jump start in `player_physics_sub`; added to `CompressedState`, so every case's
byte count may shift by one — only the 1-1 cases were rebuilt); `W11PipeSpeedup` → `WithRunningTimer`
(state 11 bytes). The XPos table (`xpos-dump`) is unchanged: its substate has no running timer and the
max-distance path holds B anyway.

**Conclusion (F56).** With the two fixes the model is frame- and subpixel-exact on every field on 82,524
random/mutated frames in the 1-1 third room after the goombas (roots 1150/1230), including 596 grabs and 71
core-confirmed glitch grabs. Enemies remain outside the model: the third room's only enemies are the goomba
pair from `E_GroundArea6` page 11 col 1 (`id $37`), already walking at room load on fixed trajectories
(F58) — the next sub-unit models them as frame-indexed obstacles.

## Goombas (P2.1b-m2, session 4)
`room_enemies` (smb-opt patch, `src/main.rs`): the third room's goomba pair as frame-indexed obstacles
(F58: x = 2768 + 24i − ⌊(f − 1044)/2⌋ after frame f, Y 184; F59: collision check only on odd model frames =
even `FrameCounter`, `BoundBoxCtrlData` boxes, stomp iff integer y speed > 0 or a stomp earlier in the frame,
else death; 2 bits per goomba: stomped, collision d0). First version had the parity and the position law off
by one frame (inherited from the dump's row convention) — the differential test found both (55 → 16 → 0
differing trials). The trace parser also had to accept `LEFT | RIGHT | LR` (facing after L+R); before that
fix every suite silently stopped at the first ground L+R frame (results valid, coverage shorter). Final
suites with goombas, from the first control frame (record 1048): `--n 200 --len 120 --seed 11` 22,444
frames / 58 deaths; `--n 300 --len 100 --seed 12 --mutate 3` 28,816 / 45 deaths; `--n 200 --len 245 --seed
14 --mutate 3` 46,075 / 37 grabs (35 FPG) / 16 deaths — 0 differences (`runs/P2.1b-model/difftest_goombas_*`).
The WR's bounce at step 65 and grab at step 239 reproduce with no injection (`trace11room`).
