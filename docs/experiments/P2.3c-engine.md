# P2.3c-1 — `bfscx`: the external-memory search engine for any case

Date: 2026-08-22 (session 7, late). Unit: P2.3c-1 (STATUS). Engine: `third_party/smb-opt` + `tools/smb-opt-modes.patch`
(`bfscx_run`, `bfscx_path` in `src/main.rs`). Tools: `tools/replay_check.py`.

## Goal
`bfs11c` (the engine that survived run 4: parents streamed from layer files, bounded per-thread accumulators spilled
as sorted runs, k-way merge, `--resume`) was hard-wired to 1-1 room 3 (goomba byte, FPG goal). `bfsc` (generic over
cases, object hook, the case's `SearchGoal`) keeps the whole frontier and a global visited set in memory and explodes
on 4-2. P2.3c needs both: `bfscx` = `bfsc`'s semantics with `bfs11c`'s memory behaviour.

## Design
- `bfscx CASE INPUTS FIRST PREFIX MAX_STEPS [--lift N] [--layer-dir D] [--resume N] [--acc-mb M] [--stop-step N]
  [--threads N] [--check-path N] [--out F]`. Records are 24 bytes: the case's compressed key (≤ 22 bytes; W42Main 20,
  W42Warp 14, W11VertPipeEntry 10) + the hook's ext (u16 LE). Dedup per layer on (key, ext) by sort/merge; no global
  visited set (a state re-reached at a later frame is a different node of a frame-indexed search).
- Per child: goal test (`is_goal_state` on the step result, before the hook, as `bfsc`), then the hook
  (lift), dead if `y ≥ 0x1d000`, then the case's `distance_to_goal_heuristic` (None → pruned; `step+1+h > MAX_STEPS`
  → pruned). Stops at the first layer with a goal — the optimum under the deadline — and prints the goal's parent
  record + input and the `bfscx-path` command.
- `--check-path N`: replays N more input records (the WR's continuation) through the model + hook and, after each
  merge, binary-searches the sorted layer file for the reference record ("in the frontier" / "NOT … (x y ext h)").
- `bfscx-path CASE LAYER_DIR STEP RECORD INPUT [--lift N] [--threads N] [--out F]`: backward reconstruction by a
  threaded full scan of each lower layer (hook applied, ext compared), RLE print, NES-order bytes.
- `tools/replay_check.py --case C --first R --prefix N --path F [--lift A] [--down] [--extra K]`: WR prefix +
  reconstructed bytes (+ Down on the last record, F74) on the QuickNES core vs the model; reports mismatches and the
  core's GES-3 frame.
- Memory: `--acc-mb` per thread (default 64) + a 24 MB chunk buffer per thread; run under `systemd-run --user --scope
  -p MemoryMax=…` always (STATUS rule after the 20:09 OOM).

## Notes
- F88 is the first search result that beats HappyLee on the core; it is inside 4-2's framerule deficit (13 → 10 on the
  WR's own route) so it changes nothing on the clock, but it shows the WR's final approach to the wrong-warp pipe
  (braking from speed 0x28 to 0x11) is not frame-optimal — the 2-frame top-route claim (F36) should be re-measured
  with the same tooling once the main-area bound exists.
- The `bfsc` ↔ `bfscx` difference in early 1-1 layers is a semantic choice, not a bug; for proof runs the per-layer
  dedup is the sound one (a state at frame f+1 is not the state at frame f when enemies/objects depend on the frame).
- Not done here: `--reduced` inputs (F76, not proven lossless), the landing bound of P2.1b-m3, and the staged bounds
  (P2.3c-2) — the engine takes whatever the case's `SearchGoal` returns.
