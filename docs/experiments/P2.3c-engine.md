# P2.3c-1 — `bfscx`: the external-memory search engine for any case

Date: 2026-08-22 (session 7, late). Unit: P2.3c-1 (STATUS). Engine: `third_party/smb-opt` + `tools/smb-opt-modes.patch`
(`bfscx_run`, `bfscx_path` in `src/main.rs`). Tools: `tools/replay_check.py`.

## Goal
`bfs11c` (the engine that survived run 4: parents streamed from layer files, bounded per-thread accumulators spilled
as sorted runs, k-way merge, `--resume`) was hard-wired to 1-1 room 3 (goomba byte, FPG goal). `bfsc` (generic over
cases, object hook, the case's `SearchGoal`) keeps the whole frontier and a global visited set in memory and explodes
on 4-2. P2.3c needs both: `bfscx` = `bfsc`'s semantics with `bfs11c`'s memory behaviour.

## Design
- `bfscx CASE INPUTS FIRST PREFIX MAX_STEPS [--lift N] [--layer-dir D] [--resume N] [--acc-mb M] [--stop-step N]
  [--threads N] [--check-path N] [--out F]`. Records are 24 bytes: the case's compressed key (≤ 22 bytes; W42Main 20,
  W42Warp 14, W11VertPipeEntry 10) + the hook's ext (u16 LE). Dedup per layer on (key, ext) by sort/merge; no global
  visited set (a state re-reached at a later frame is a different node of a frame-indexed search).
- Per child: goal test (`is_goal_state` on the step result, before the hook, as `bfsc`), then the hook
  (lift), dead if `y ≥ 0x1d000`, then the case's `distance_to_goal_heuristic` (None → pruned; `step+1+h > MAX_STEPS`
  → pruned). Stops at the first layer with a goal — the optimum under the deadline — and prints the goal's parent
  record + input and the `bfscx-path` command.
- `--check-path N`: replays N more input records (the WR's continuation) through the model + hook and, after each
  merge, binary-searches the sorted layer file for the reference record ("in the frontier" / "NOT … (x y ext h)").
- `bfscx-path CASE LAYER_DIR STEP RECORD INPUT [--lift N] [--threads N] [--out F]`: backward reconstruction by a
  threaded full scan of each lower layer (hook applied, ext compared), RLE print, NES-order bytes.
- `tools/replay_check.py --case C --first R --prefix N --path F [--lift A] [--down] [--extra K]`: WR prefix +
  reconstructed bytes (+ Down on the last record, F74) on the QuickNES core vs the model; reports mismatches and the
  core's GES-3 frame.
- Memory: `--acc-mb` per thread (default 64) + a 24 MB chunk buffer per thread; run under `systemd-run --user --scope
  -p MemoryMax=…` always (STATUS rule after the 20:09 OOM).

## P2.3c-2 — staged / coupled bound for the warp zone (2026-08-22, session 7, late)
**Geometry** (`data/blockmaps/w42_warp.txt`): roof row 2 cols 48–59; gap cols 60–61 (x 960–991); right wall cols 62–63;
pipes at cols 50–51 / 54–55 / 58–59 rows 8–10 under the roof; staircase cols 40–48 rows 3–10 solid. Necessary
conditions for any route: X ≥ 957 (foot points x+3, x+12 over the gap) and Y ≤ 32 (over the roof), then ≥ 96 px down.
**Bound** (`W42Warp::distance_to_goal_heuristic_ext`, phase in the hook's ext via `--stage`: ext = 1 once X ≥ 957):
- ext 0: max( max(x-steps to X ≥ 957 + C_RET, coupled two-phase x-steps), ceil((Y−32)/5) + 22 ), C_RET = 70 = the
  x-table's min return (X 957 → X ≤ 812.99) over the 29,964 reachable classes moving right ≥ 1 px/frame;
  coupled = `XPosHeuristic::build_overshoot_bound`: for each distinct return cost r ∈ {70..75} a max-displacement DP
  over the class graph restricted to END in a right-moving class with return cost ≤ r (horizon 96, then vmax per
  step — always an upper bound on displacement, so truncation only loosens), bound = min_r (k_r(957 − x) + r).
  First version without the right-moving restriction let paths "end" in left-moving classes after an overshoot and
  gained nothing (460); the restriction is sound (the first crossing is a right-moving step) and gives 461.
- ext 1: max(x-steps to X ≤ 812.99, ceil((128 − Y)/4.5)). MrWint's y-table is **not** used for descents: a head bonk
  turns −4 into +1 instantly, faster than free flight, so only the speed caps are admissible for y.
- Plain (ext-less) `distance_to_goal_heuristic` = the ext-1 form (sound in both phases).
**Controls** (2–3 GB caps, 4 threads): `bfscx W42Warp … 7247 0 475 --stage --check-path 476 --stop-step 24`: root 461
(x-only 329, WR 476), 0 bound violations on 476 steps, slack profile 15 frames constant until step 380, consumed in
380–440 (`warp_stage3_p0_d475.log`); `… 7247 400 76 --stage --check-path 76`: complete in 1054 s, goal at layer 76
(12.4M transitions), WR in the frontier throughout, peak 21M states/layer; `… 7247 400 75`: no live states after
layer 23 → the WR's return is optimal from its drop state (F90). Growth with the 461 bound: 9.2M at layer 24,
×1.25/layer (F91). A mistaken first run with deadline 475 from prefix 400 (= 475 *more* steps, no pruning) reached
102M states at layer 32 before being killed — `MAX_STEPS` counts from the prefix root.
**Conclusion.** The bound is now within 15 frames of the WR and the slack is localized (drop/fall/landing), but the
exact frontier at 15 frames of slack is beyond the laptop; the proof run needs the cloud and an end-game (x,y) bound
(or a Phase-B multi-root search from all drop states, H35). Main-area gates (pipe A / bricks / pipe B) not started.
