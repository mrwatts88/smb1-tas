# P2.3b-2 — block states in the 4-2 model (bumped bricks / question blocks)

Date: 2026-08-22 (session 7). Unit: P2.3b-2 (STATUS). Engine: `third_party/smb-opt` + `tools/smb-opt-modes.patch`
(`Options::BlockStates`, `State.blocks`, `W42MainBlocks`). Checker: `tools/block_state_check.py`.

## Goal
Close the last main-area model gap found in P2.3b (F81): after a head bump the bumped cell is `$23` (solid) for a
while and question/hidden/item/coin bricks end up `$c4`; the static block map got every trial that bumped a block
wrong from that frame on. Acceptance: 0 differences on ≥ 100 block-bumping mutated trials.

## What the game does (read from `data/disasm/smbdis.asm`, verified on the WR dump)
1. **Fresh bump** (small Mario, `BlockBounceTimer` 0, metatile is a brick/question block): `PlayerHeadCollision`
   (7219–7305) writes `$23` into the block buffer cell, `DestroyBlockMetatile` into `VRAM_Buffer1`, sets
   `BlockBounceTimer` = 16, creates a block object (`Block_State` $11, slot = `SprDataOffset_Ctrl`, toggled per bump)
   with `Block_Y_Speed` −2 / `Block_Y_MoveForce` 0 (`BumpBlock`) and decides `Block_Metatile`: `$c4` if the metatile is
   in `BrickQBlockMetatiles` ($c1 $c0 $5f $60 $55–$5e), except coin bricks `$58/$5d`: first bump sets
   `BrickCoinTimerFlag` and `BrickCoinTimer` = 11 (an **interval** timer, $079d ≥ $0795: ticks when
   `IntervalTimerControl` wraps, every 21 frames), and the brick stays a coin brick while flag set & timer ≠ 0; flag set
   & timer 0 → `$c4`. Plain bricks ($51/$52, not in the table) restore as themselves. `BrickWithCoins` (area parser,
   4184) clears the flag whenever a coin-brick object is rendered.
2. **Bounce** (`BlockObjectsCore`/`BouncingBlockHandler`, `ImposeGravityBlock`: force +$50/frame, max speed 8): the
   block object returns to its origin row (y low nybble < 5) on the 13th frame after the bump and sets `Block_RepFlag`.
   The leftover `SprObject_YMF_Dummy` fraction (never initialised for the block slots) does not change this: all
   256 values return on frame 13 (`tools/block_bounce_sim.py`, reproduced below).
3. **Restore** (`BlockObjMT_Updater`, 7502, runs in `GameEngine` *after* the player routine): writes `Block_Metatile`
   back into the block buffer — **only if `VRAM_Buffer1` is empty** at that point. So the player sees `$23` on frames
   1–14 after the bump (`BlockBounceTimer` 15..2) and the restored tile from frame 15, unless `VRAM_Buffer1` is busy.
4. **`VRAM_Buffer1` occupancy.** Writers before the updater in a frame: a coin award (`GiveOneCoin` → status-bar
   digits) and a fresh bump (`DestroyBlockMetatile`); after the updater: the restore write itself, `ColorRotation`
   (every frame with `FrameCounter & 7 == 0`), `RunGameTimer` (the timer digits every 24 frames, `GameTimerCtrlTimer`).
   The NMI transfers and clears `VRAM_Buffer1` **only when `VRAM_Buffer_AddrCtrl` is 0**; when it is 6 (the column
   renderer's `$0341` buffer: `RenderAreaGraphics`/`RenderAttributeTables`; a coin erase `RemoveCoin_Axe`;
   `CheckTopOfBlock`) the buffer is left alone and still blocks the next frame's updater. Dump example: the coin award
   at row 6789 sat in `VRAM_Buffer1` through row 6793 behind a render burst.
5. **Area parser schedule** (F78 refined): a burst of 8 tasks starts when `ScrollThirtyTwo` ≥ 32 and
   `AreaParserTaskNum` is 0 (task 7 `AreaParserCore` on column C, 6/5 `RenderAreaGraphics`, 4 `IncrementColumnPos`,
   3 `AreaParserCore` on C+1, 2/1 render, 0 increment + `RenderAttributeTables`); tasks 6, 5, 2, 1 and the attribute
   write set `AddrCtrl` = 6; the parser is skipped on frames where `AddrCtrl` is already 6 (coin erase). Columns:
   2 per burst starting from `CurrentPageLoc·16 + CurrentColumnPos` = 24 at the 4-2 control row; (43,2) was
   processed at ScreenLeft 334 (burst 10, second half) and (77,7) at 874 (burst 27, second half) — both match.

## Model (`src/options.rs`, `src/state.rs`, `src/emu.rs`, `src/case/w42.rs`)
`Options::BlockStates` (default `NoBlockStates`: no behaviour or key change for other cases and run 4).
`State.blocks` (56 bits in the key; W42Main key 13 → 20 bytes): `bounce_cell` (11 bits: the cell reading `$23`),
`used` (16 bits over `W42MainBlocks::CELLS`: cells reading `$c4`), `coin_brick_flag`/`coin_brick_timer`, `frame`
(mod 168 = lcm(8, 21, 24): derives `IntervalTimerControl`, `FrameCounter & 7`, `GameTimerCtrlTimer` from the case's
start phases `IP0/FC0/GT0`), `aptn`, `burst_pending`, `parser_col`, `vbuf1`, `addrctrl6`. Per frame: NMI part
(interval tick, frame, flush rule), player part (`block_buffer_collision` reads `$23`/`$c4` through the state; fresh
bumps and coin awards mark `VRAM_Buffer1`/`AddrCtrl`), GameEngine part (updater restore when due and free,
ColorRotation/game-timer writers, parser burst/tasks/coin-brick flag reset). `W42MainBlocks::CELLS` = the 16
convertible cells of BB42: coin bricks (43,2) (77,7); question blocks (50,3) (51,3) (50,7) (51,7) (54,7) (56,7);
powerup block (55,7); hidden blocks (64,5) (63,6) (65,6) (66,7); item bricks (28,7) mushroom, (64,3) vine,
(81,7) star. The 269 plain bricks only bounce.

## Known approximations (documented, none triggered in the trials)
- A fresh bump while the previous cell's restore is still pending (needs `VRAM_Buffer1` busy on ≥ 2 consecutive
  due frames, then a bump at timer 0) would use the game's second block slot; the model restores the old cell at
  once instead (`fresh_bump`).
- Spawned items are not modeled: bumping (28,7)/(55,7) (mushroom), (81,7) (star) or (64,3) (vine) creates an object
  that can touch Mario; routes that collect an item are outside the model (STATUS "Model omissions", H34).
- `ColorRotation` skips its write when `VRAM_Buffer1_Offset` ≥ $31 (buffer nearly full) — ignored (never the case
  with at most a coin award + a block write per frame).
- `CheckTopOfBlock` (a coin directly above the bumped cell) never applies in 4-2 main (no such pair in BB42).
