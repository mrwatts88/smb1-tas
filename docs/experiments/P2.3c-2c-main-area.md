## The y-coupled bound (2026-08-23, session 9): `heuristics::ygate` + `bfscx --goal-x GX --goal-y GY`
**What it is.** A sound lower bound on the steps until `x_pos >= GX && Player_Y <= GY` hold *at the same step*, built
from two relaxations and joined per step count k:
- x: MrWint's x table (max gain in exactly k steps for the state's x class) — unchanged;
- y: the model's vertical rules exactly (`emu.rs`: jump start at −5/−4 px with the jump gravity kept only while A is
  held and y speed < 0, A release irreversible, `y += y_spd; y_spd += v_force` with the MAX_Y_SPD clamp, a head bump
  sets `y_spd = 0x100 | frac`, a landing needs `y_spd >= 0` and Y ∈ [Ys, Ys+5) and snaps Y to Ys), with x dropped
  except through **surfaces**: every standable cell top of BB42 (cell ≠ 0, not coin/climb; hidden blocks included)
  as (Ys = 16·row, the x_pos intervals where one foot point x+3/x+12 is inside a cell of that row). This is a
  superset of the model's landings on purpose: a one-frame landing inside a wall face is SMB1's wall jump, and the
  floor-level wall walk (F80) makes every row of a solid run standable — so the faces of the pillar (Y 128/144 at
  x ≥ 340), the rows inside the brick run and the pit walls are all surfaces. Head bumps are allowed on any frame
  with y speed < 0 (the model also needs Y mod 16 ≥ 4 and a block above — superset).
- per state: the hold-A trajectory is pointwise the highest relaxed trajectory (a release or bump only lowers it),
  so "Y ≤ GY at step k without landing" ⇔ k in its window; the earliest frame a landing on surface s can happen is
  max(first hold-A frame with Y ≤ Ys+4 (s above) or fastest-descent frame with Y ≥ Ys (s at/below: bump-at-1 or
  release, whichever lands first), x-table steps to bring x into one of s's intervals); after a landing the
  y-only T(Ys) (min steps from standing at Ys to Y ≤ GY over jump/landing chains through higher surfaces, precomputed
  top-down) applies; standing states may wait, so their feasibility is "k ≥ t". The bound = the first k at which the
  x table allows x ≥ GX **and** Y ≤ GY is y-feasible (window or re-landing). Code: `src/heuristics/ygate.rs`
  (doc comment = the argument), `W42Main::set_position_goal/steps_until_xy`, `xy_h` in `bfscx`, trace mode `traceh`.
**Known looseness (sound, listed for the next tightening).** T is computed with landings every 16 px on wall faces
(T(176 → 112) = 12 via four one-frame face landings, vs 18 for a single running jump); in the model each face landing
is followed by the side-check push-out (−1 px, speed zeroed), so two consecutive face landings need the feet back
inside the column, which the re-acceleration (< 1 px/frame) cannot do — proving that would make T(176) = 18 and the
face surfaces single-use. Inside the brick run (F80) hops land at Y 160 but every hop bumps the brick above, so the
relaxed chain 160 → 144 → … is also unrealizable there. Neither matters for S1 (those surfaces are at x ≥ 340).
**Validation.** (1) The WR-suffix regression control is byte-identical (same counts 6, 16, …, 257001; the position
goal is not used there): `runs/P2.3c-2c/regr_w42main_p575_d587_ygate.log`. (2) `tools/ygate_audit.py` — random
right-biased trajectories from the root (A held in random runs, B mostly held) traced by `smb-opt traceh`, asserting
at every step with a later goal step t' that t' − t ≥ h: **300 trials × 230 steps, 8 reach the goal, 1,485 checks,
0 violations, min slack 0** (`--gx 339 --gy 112 --lift 0 --n 300 --len 230 --seed 1`). (3) On the WR
(`traceh … 588`, `runs/P2.3c-2c/traceh_wr_s1.log`): h 137 at the root (the fall is not y-binding), 12 inside the
run (the face-chain T(176)).
**Tooling note.** `systemd-run --user --scope -p Nice=10` is rejected on this host ("Unknown assignment: Nice=10" —
scope units take no Nice= property), which silently aborted the first ladder attempt; `tools/bfscx_ladder.sh` now runs
`nice -n 10 smb-opt` inside the capped scope. The x-table build (~22 s) dominates each short ladder attempt.

## P2.3c-5 (2026-08-24, session 13): the scroll-aware drift bound — why the rungs blew up, and the fix

**The roadblock.** The two dedicated drift-campaign rungs (local d58, Mac d62) were both watchdog-killed at layer 37,
frontier 126M / 249M, `max x 0x530f0` = 1328.94 px = the relative-112 refusal wall exactly, `goals 0`. Growth was
×1.5–1.6/layer from layer 35. These are **not verdicts** — the searches ran out of memory, they did not report "no
path." Diagnosis: `W42Main`'s case bound under `--enemies` was the **x-only** table to X 1348 (`get_steps_until_x_pos_at_least`).
That table is blind to the F120 scroll requirement, so every state pinned against the wall at x 1328.94 — millions of
them, differing only in Y, block phase and enemy ext — looked ~2 frames from the goal (Δx = 19 px ≈ 8 frames of run,
but with the y-term satisfied the join returned the smaller x-term) and survived to the deadline. The frontier filled
with wall-pinned garbage that can never mint the offset the warp needs.

**The fix: `heuristics::drift::DriftBound`** (new engine file; `bfscx --enemies` case goal, ON by default, `--no-drift`
to disable). A sound lower bound that understands the scroll. Model facts it rests on (emu.rs, all verified in the
existing model): the scroll offset `rel = X − ScreenLeft` changes per frame only by (a) this frame's integer movement
dx while `rel < 0x70` (0x50–0x6f: dx−1 for dx≥2; F77), **never once `rel ≥ 0x70`** (exact tracking) — *except* during
the ≤ 15 frames after a side collision (`side_collision_timer`), when nothing scrolls; and (b) a collision push
(`impede_player_move`: +1 px when moving non-right with speed < 1 px/frame, −1 px moving right), which never scrolls
and needs a collision point inside a solid cell. The F40 refusal (`sl16 ≥ 1217` pruned) makes `X ≤ 1328 + m` a wall
every surviving state respects (m = rel − 0x70). So: a relaxed BFS over `(X px ∈ [1180,1360], Player_Y ∈ [0,192), m ∈
[−40,24], credit c ∈ [0,C])` with per-step transitions {plain move |dx|≤3 |dy|≤5 gaining offset only per the scroll
regime; a "credit" 1-px unscrolled move (the side-collision window, c−1); a push at a site read from BB42 with Mario's
foot/side collision-point adders (feet depth ≥5, sides Y≥8), landing with full credit}, always inside the wall; BFS
distance from `{X ≥ 1348}` to each state = the bound. Every model transition of a surviving state maps to one relaxed
transition of cost 1 (domain edges clamp with permissive gain ranges; below-domain X answers 0), and the query uses the
full credit C (distance monotone in c), so `h` is admissible. The credit budget C = the max movement in the 15
unscrolled frames from a side-zeroed speed (`XPosHeuristic::max_gain_below_speed`, G(1..15) = 1..15 px) → **C = 16**.
The case bound becomes `max(x-table, drift)`; a second fix refuses the **goal transition itself** when its own frame
scrolled to `sl16 ≥ 1217` (`goal_refused` in main.rs — the search tested the goal before the hook ran, so a
wrong-scroll pipe entry was being counted as a win).
