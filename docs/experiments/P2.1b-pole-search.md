# P2.1b — 1-1 pole approach: exact search from the WR's stairs-top state

**Goal (part 3 of P2.1b, H27).** From the WR state after QuickNES frame 1229 (stairs top, X 3033,
Y 48, speed 40, T 372), is there any input sequence that grabs the flagpole at frame ≤ 1284 (the WR:
1285)? A hit with T = 370 would move 1-1 to the next framerule (T_set ≤ 1813, −21 frames).

**Setup.** `src/search/bfs.c` (v1, full savestates) and `src/search/bfs_par.c` (v2: 2 KiB RAM
states + template savestate (F50), 10 forked workers, shared-memory arenas, parent-side dedup).
Sound pruning: speed +≤2/frame, cap 40 (F48); drop states that cannot reach x ≥ 3158 (F51) by
frame 1284. Inputs: 16 A/B/L/R combinations per frame.

**Commands.** See `runs/P2.1b-root1229/README.md` (v1) and `runs/P2.1b-root1229-par/README.md` (v2).

**Engine versions.** v1 `bfs.c` (12.8 KB savestates); v2 `bfs_par.c` (2 KiB RAM + template savestate, F50; 10 forked workers); v3 (compact states: only the bytes at addresses that ever differ from the root RAM, LMAX 384, ~200 used; verified to produce the identical state set as v2 at layer 7); bounds: (a) speed +≤2/frame (F48), (b) `--xpos-table`: MrWint's XPos max-distance table exported from smb-opt (`xpos-dump`, 70,688 x-physics classes keyed by $57:$0705, quantized $0700, $45, $33, $1D==0, $0703≠0) giving the exact model-derived minimum frames to reach x ≥ 3158, (c) `--y-target 162`: best-case descent (8.8 y speed += $90 per frame, cap 4 px/frame, +1 px rounding). Template caveat (F50): roots at/adjacent to lag frames break the reconstruction (root 923 collapsed to 1 state/layer) — use roots ≥ 930.

**Results so far.**

  3,608, 11,616, 30,928, 70,096, 132,684, 219,936, ≥245,300 (cap; 950k children overflowed);
  pruning grows fast (layer 10: 289k pruned vs ~1.2M kept). 840 s single-threaded.
- v2 reproduces v1's counts and runs ~4.5× faster on 10 workers (layer 7: 12 s vs 54 s). Its long run
  (`runs/P2.1b-root1229-par`) hit the 1.52M cap at layer 14 (frame 1243): 16, 127, 847, 3,608, 11,616,
  30,928, 70,096, 132,684, 219,936, 354,364, 489,820, 709,928, 1,087,176, 1,518,208+ (×1.4/layer,
  pruned 289k→76k/layer, no terminal). v3 without new bounds reached the same 1.09M at layer 13

- Bounds (b)+(c) from root 1229: layer 11 = 292,660 vs 489,820 (−40%); pruned 103k at layer 7.

  37,815 / 66,281 / 119,502 unique states vs 107,757 / ≥245,300 / — without it (xunk = 0: every

## Model-side search (P2.1b-m, session 4, 2026-08-21)
**Why.** The core run v4 (same root, bounds a+b+c) reached layer 18 (frame 1247) with 1.94M states at
500 s/layer (×1.25/layer) and was killed by the out-of-memory killer together with a model run; it would have
hit its 7 GB cap around layer 26 anyway. `runs/P2.1b-root1229-v4/stdout.log` is the record (inconclusive).
The validated player model (F53, F56) has no enemies — and none are ahead of the stairs top — so the same
question can be asked of the model with 11-byte states.

**Tool.** `smb-opt bfs11 INPUTS FIRST PREFIX MAX_STEPS [STEP:yspd=V] [--root-frame F] [--any-y] [--out FILE]`
(`tools/smb-opt-modes.patch`): replays the WR prefix in the model (goomba bounce injected at step 66),
then a layered BFS over all 16 A/B/L/R inputs, global dedup on the compressed player state (sound because
the model is time-invariant: the same state seen later can do nothing the earlier copy could not), bound =
MrWint's `BoundsHeuristic` (`get_steps_until_bounds_at_least(x ≥ 0xc5600, y ≥ 0x1a200)`, exact precomputed
x and y gain tables), deadline = MAX_STEPS. Records every `StateChangeFlag` with step/x/y and whether it
is a glitch grab (Y ≥ 162, F55); prints the earliest grab's input sequence (RLE) and writes it as
NES-order bytes. Memory ≈ 35 B/state (11-byte key, u32 parent, u8 input, frontier states only); the first
version kept full `State`s (≈130 B/state, 7 GB at 55M states — the OOM).

**Command.** `smb-opt bfs11 data/wr/wr_inputs.bin 1048 184 55 66:yspd=-1024 --root-frame 1229 --out …`
(prefix 184 records = frames 1046–1229; 55 steps = frames 1230–1284).

**Result (root 1229, deadline 1284).**
- Model as cloned (`NoRunningTimer`, held-A jumps — a relaxation of the real game in both respects, see
  `P1.2-lite-smb-opt.md`): layers 8, 55, 247, 814, 2,099, 4,044, 5,567, 10,085, 17,469, 27,996, 34,723,
  36,930, 38,700, 50,613 (frame 1243; the core had 667,076 at the same frame — 17× more, its RAM carries
  non-physics variety), … peak 6,280,121 at frame 1275, then the bound bites; 55.3M states visited, 380 s,
  **no glitch grab**. Grabs exist from frame 1279 (Y 152, X 3161) on; the lowest grab by frame 1284 has
  Y 161.875 (0x1a1e0) — one pixel above the glitch threshold, and a non-glitch grab waits ~47 frames for
  the flag (F55). `runs/P2.1b-model/root1229_d55.log`, compact re-run identical: `root1229_d55_v2.log`
  (163 s, 2.2 GB RSS).
- Corrected model (`WithRunningTimer` + `a_held`, exact on 82k random frames, F56): see
  `root1229_d55_v3.log` — stopped by hand at layer 48 (frame 1277): 34.8M states in the frontier, 182M visited, no grab, 9.6 GB RSS + 4.3 GB swap (9:42). The exact model has ~5× the states of the relaxed one (running timer × A-held). **Relaxation argument** (why the as-cloned run is already the proof): for every real input sequence there is a model input sequence with the same trajectory — set B whenever the real game has the run cap through `RunningTimer` (B has no other effect for small Mario), and clear A on ground frames where the real game ignores a held A (`GetPlayerAnimSpeed` masks A out; A has no other ground effect). So the relaxed model's reachable set ⊇ the real game's, and "no glitch grab ≤ 1284" transfers. Use the relaxed model for proofs and the exact one (or the core) for candidates.
- Heuristic at the root: 50 steps, i.e. x ≥ 3158 is unreachable before frame 1279 from this state (exact
  x-physics table), so the WR's arrival at 1280 is within one frame of the x-optimum from the stairs top.

**Whole room.** From the room's fixed entry state (frame 1045, F47) the same exact x-table gives 233 steps:
x ≥ 3158 cannot happen before frame 1278 on flat ground (the crude ≤ 2/frame bound said 1272, F48). The
WR reaches 3157.3 at 1280 and grabs at 1285 after the 5-frame embed creep; the deadline 1284 leaves 6
frames of slack over the x-bound, which is what keeps a whole-room BFS small. The enemy-free model probe
from frame 1045 (`root1045_d239.log`): exact model, `ulimit -v 9.5 GB`: ×1.19/layer at layers 20–25 (736k unique at frame 1070, 3.7M visited) — it will exhaust the cap long before the deadline; left running at session end as a growth record. The relaxed model and per-layer dominance/bounds are the levers (P2.1b-m2). The goombas (F58) are not in the model yet: a path
through them is invalid (death), and the WR's bounce is unavailable — so that probe is neither a proof nor
a complete candidate search; the goomba sub-unit (P2.1b-m2) closes both gaps.

**Conclusion.** H27 is refuted for the WR's stairs-top state (proof: exhaustive model BFS, sound dedup and
bounds, model exact on the relevant mechanics). Any 1-1 gain must come from an earlier divergence from the
WR (the first 183 control frames of the third room, or rooms 1–2, which fix the entry frame).
