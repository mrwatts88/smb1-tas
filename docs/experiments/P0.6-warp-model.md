# P0.6 — warps & area loading: code study + ROM tables + dump traces

**Goal.** Every player-influenceable table index in the warp/area-loading paths, with its
out-of-bounds behaviour; decide whether the warp system allows anything faster than the WR's
1-2 → 4-1 → 4-2 → 8-1 structure. Deliverable: `docs/warp-model.md`.

**Setup.** Disassembly `data/disasm/smbdis.asm`; ROM `roms/Super Mario Bros. (W) [!].nes`
(classic header, verified F1); WR full-RAM dump `data/wr/fceux_wr.ram` + `fceux_wr.csv` (P0.3).
Machine: Linux box. No emulator runs were needed.

**Commands.**
```
python3 tools/warp_tables.py                 # table addresses, every WZC×pipe lookup, bogus-world
                                             # pointers, WorldNumber-indexed OOB bytes
python3 tools/area_data.py E_UndergroundArea1 L_UndergroundArea1 \
        E_UndergroundArea2 L_UndergroundArea2 E_GroundArea16 L_GroundArea16
grep -o -E '^E_[A-Za-z0-9]+' data/disasm/smbdis.asm | sort -u | xargs python3 tools/area_data.py \
        | grep -E '^E_|AREA-CHANGE'           # the complete row-$0E command table
python3 tools/ram_trace.py data/wr/fceux_wr.ram 3500 3730 ScrollLock WarpZoneControl \
        Enemy_ID+0 Enemy_ID+1 Enemy_ID+2 Enemy_ID+3 Enemy_ID+4 Player_Y_Position ScreenLeft_PageLoc --changes
python3 tools/ram_trace.py data/wr/fceux_wr.ram 7600 7724 ScrollLock WarpZoneControl \
        Enemy_ID+0 Enemy_ID+1 Enemy_ID+2 Player_PageLoc ScreenLeft_PageLoc AltEntranceControl \
        GameEngineSubroutine WorldNumber AreaPointer --changes
```
Area-load rows (lag rows) with `AreaPointer`/`EntrancePage`/`AltEntranceControl` were read from
the csv+ram with a 10-line inline script (pattern in `tools/ram_trace.py`).

**Results.**
- Tables: `WarpZoneNumbers` $87F2, `GameTextOffsets` $87FE, `WorldAddrOffsets` $9CB4,
  `AreaAddrOffsets` $9CBC (36), `EnemyAddrHOffsets` $9CE0, `EnemyDataAddrLow/High` $9CE4/$9D06,
  `AreaDataHOffsets` $9D28, `AreaDataAddrLow/High` $9D2C/$9D4E, `HalfwayPageNybbles` $91BD,
  `BowserIdentities` $D736, `Hidden1UpCoinAmts` $B2C2.
- WZC×pipe destinations: see `docs/warp-model.md` §5.5. WZC 1 left/right → WorldNumber 35 →
  AreaPointer $01 (Water2) = the NES Minus World; WZC 3/7 → WorldNumber 255/38 → $9D/$00.
- Dump: 1-2 enemy $34 loaded row 3471, lock row 3545, enemy fired row 3546 (WZC 1), text row
  3721 (WZC 4). 4-2: loads at rows 6045 ($29 intro), 6544 ($41 main), 7223 ($2F, mode 1 = the
  wrong warp: pipe taken before the page-5-col-15 coin-room command was parsed), text in $2F
  at row 7608 (WZC 6), pipe at row 7724 with X 114 → world 8. No $34 enemy ever in $2F
  (its enemy data is a single $FF). 8-4 loads: $E5 p7, $65 p12, $02 p0, $65 p16, all mode 2.
- Layout columns (page:col): 1-2 lock 11:2, enemy 11:2, pipes 11:2/6/10, text 12:6; 4-2
  ceiling zone lock 12:4, enemy 11:8, pipe 13:6, text 14:6; $2F pipes 3:2/6/10, text 4:6.
- `InitializeArea` clears $0000–$074B and $0780–$07A1: WZC/ScrollLock reset per area,
  AreaPointer/EntrancePage/AltEntranceControl/World/Level/Area/HalfwayPage/ITC survive.
- No area's enemy data contains ids $3C–$3F (the only ids that would leave the init jump
  table); header/entrance indices are all in bounds.

**Conclusion.** WZC ∈ {0, 1, 4, 5, 6} at any pipe entry (code-level proof in
`docs/warp-model.md` §5.4: one self-erasing +1 object per visit, text unreachable while the
scroll is locked, both cleared per area). Reachable warps: 1-2 → {4,3,2} or {−1,5,−1};
4-2 ceiling → 5; 4-2 $2F → {8,7,6}. World 8 only from 4-2 → the WR's warp structure is the
fastest the tables allow. Pipe destinations are exhaustively tabulated; the only castle-page
writers are 8-4's own commands, with the Bowser room (page 16) written only by the water
section. Completion = axe with WorldNumber ≥ 7. H5 refuted; H6/H13 refuted at table level
(corruption paths fold into H7); new concrete targets for P3.x recorded in hypotheses.
