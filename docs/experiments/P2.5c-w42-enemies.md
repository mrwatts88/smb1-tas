## Finding: the enemy loader sees the previous frame's `AreaParserTaskNum` (F78 amended)
`GameEngine` (`smbdis.asm` 5311–5373) runs the six enemy slots (`EnemiesAndLoopsCore` → `ProcessEnemyData`) and only
at its end the parser task (`RunParser`), where a burst starts (value 8 → 7 after the frame). The loader's gate
`AreaParserTaskNum & 7 == 7` therefore blocks the frame *after* a burst start, not the burst-start frame. Evidence:
row 6733 consumes the page-2 area-change object with the post-frame value 7 (pre-frame 0). With the pre-frame rule
`tools/w42_enemy_sim.py` has 0 parser-state mismatches; with the post-frame rule 2 rows differ; 1-1 room 1
(`tools/room1_enemy_sim.py`) gives 0 mismatches under both (no spawn on a boundary there). The lift hook `w42_lift`
tested the post-frame value → corrected (the WR's spawn, row 6933 with value 1, is unaffected; F81 re-run below).
