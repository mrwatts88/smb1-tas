## Finding: the enemy loader sees the previous frame's `AreaParserTaskNum` (F78 amended)
`GameEngine` (`smbdis.asm` 5311–5373) runs the six enemy slots (`EnemiesAndLoopsCore` → `ProcessEnemyData`) and only
at its end the parser task (`RunParser`), where a burst starts (value 8 → 7 after the frame). The loader's gate
`AreaParserTaskNum & 7 == 7` therefore blocks the frame *after* a burst start, not the burst-start frame. Evidence:
row 6733 consumes the page-2 area-change object with the post-frame value 7 (pre-frame 0). With the pre-frame rule
`tools/w42_enemy_sim.py` has 0 parser-state mismatches; with the post-frame rule 2 rows differ; 1-1 room 1
(`tools/room1_enemy_sim.py`) gives 0 mismatches under both (no spawn on a boundary there). The lift hook `w42_lift`
tested the post-frame value → corrected (the WR's spawn, row 6933 with value 1, is unaffected; F81 re-run below).

## P2.5c-2 design — the Rust module `W42Main --enemies` (spec for the next unit)
What the 1-1 module is (`room_enemies`, `main.rs`): a per-step hook `fn(frame, &mut State, &mut g: u8) -> RoomEvent`
— goomba positions are closed-form in the frame (they spawn at the room load), the only search state is one byte
(stomped bits + the d0 latches), and the BFS keys on (player key, g). 4-2 needs more, because every spawn is
path-dependent (scroll/parser) and the objects interact (enemy–enemy turns, kicks, slot occupancy):
1. **State.** A 6-slot object array in the record's `ext` (today `u16` = the lift; grow `XREC` from 24 to 48 and
   make the hook generic over the ext type): per slot — class (3 bits: empty / goomba / koopa / beetle / plant /
   lift / item), state (4: walking, falling, flattened, resting shell, kicked, kicked-airborne, defeated, plant
   parked-down / parked-up / rising / falling), x (12 bits, px; the sub-pixel phase is bit 7 of the move force:
   1 bit), y (8 bits; plants: the travel phase), interval/frame timer (6 bits), dir (1), d0 latch (1), pair-latch
   bits (lower slots only, ≤ 4). ≈ 5 bytes × 6 = 30 bytes, plus the enemy-data cursor (which of the 6 enemy
   objects have been consumed: 3 bits), the vine/mushroom item presence (H34: 2 bits — or refuse item bumps in
   the search). Deterministic pieces need no state: a goomba's x is `x_spawn − ⌊(steps since spawn + phase)/2⌋`
   only until its first interaction, so keep x explicit.
2. **Inputs the hook already has.** `FrameCounter` parity = `blocks.frame` + `FC0` (168-cycle, in the key);
   `IntervalTimerControl` ticks (`IP0` phase); `ScreenLeft` (= `screen_left16(s)`); the parser task number and
   column (`ext` today / `blocks.aptn`, `blocks.parser_col`) for the plant spawns; Mario's pre- and post-step
   states (box, `Player_Y_Speed`) — the hook signature `fn(pre, post, ext)` is enough.
3. **Per-step order** (after the player's step and scroll, as `w42_lift`): for each slot 0..5: free → the enemy
   loader (`ProcessEnemyData` with the **previous** step's parser task, F78) — group placement into the first
   free slots at ScreenRight, singles at their column; live → offscreen mask, box, BG collision (block buffer
   BB42 + the bumped/`$23` cells from `blocks`), enemy–enemy (odd FC), player collision (even FC: stomp / injury
   = death / kick), movement, erase. Then the area parser's plant spawn (post-step task 7 or 3 at a pipe column →
   first free slot). `tools/w42_enemy_sim.py` is the line-by-line reference (F99/F100 + the asm-sourced shell/fall
   rules); port it function by function.
4. **The lift** stays as is (slot 3's class `lift` with the existing `k` counter, so slot occupancy is right).
5. **Items (H34).** A bump of (28,7)/(55,7)/(81,7)/(64,3) spawns a mushroom/star/vine that takes slot 5 (mushroom)
   or slots (vine); modelling them fully is P2.5-scope. First version: the search **refuses** bumps of the item
   cells (prune the transition) — the top route has no reason to bump them — and notes the restriction in the
   proof record; the WR's own route (which bumps two) is then outside the searched set, which is fine for the
   top-route question.
6. **Validation.** `tools/model_difftest.py --case W42Main --enemies` (new flag: compare deaths / stomps / the
   enemy slots via the core's RAM, as `--goombas` did) from record 6584 with random + mutated trials that reach
   the top floor (a bias option: A held over the entrance pits), until 0 differences incl. ≥ 100 goomba contacts
   and ≥ 20 plant/koopa contacts; then the reference-path replays of P2.3c-2c become enemy-aware automatically.
7. **Bound.** Stomps change y only (F59: bounce −4, no A boost), so the x table stays sound; the ygate relaxation
   must allow a bounce (a jump-like event from the air) whenever an enemy *could* be under Mario — cheapest sound
   form: treat a stomp bounce as a possible landing surface at the enemy's height while the enemy is alive (its
   x interval moves with it); until that is done the y-coupled bound is only used for enemy-free position goals.
8. **Size.** With `XREC` 48 the d149-class frontiers (~10⁷) cost ~0.5 GB per layer on disk; the enemy state adds
   variety only through interactions (stomp timing), so the frontier growth stays dominated by the hop variety.
