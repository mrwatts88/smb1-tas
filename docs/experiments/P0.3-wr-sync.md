# P0.3 — Sync the WR movie in two emulators; axe frame; frame alignment (2026-08-21)

## Goal / acceptance
Replay `data/wr/happylee-supermariobros,warped.fm2` (#1715M) on `roms/Super Mario Bros. (W) [!].nes`
in FCEUX and BizHawk; confirm the ending is reached; record the axe frame; document alignment
and any desync.

## Setup / exact commands
FCEUX 2.6.6 (toolbox `smb1`, Xvfb), full 2 KiB RAM + key-address CSV per frame:
```
tools/fceux_run.sh OUT=$PWD/data/wr/fceux_wr --playmov "$PWD/data/wr/happylee-supermariobros,warped.fm2" \
    --loadlua $PWD/tools/lua/wr_dump_fceux.lua "$PWD/roms/Super Mario Bros. (W) [!].nes"
python3 tools/check_sync.py data/wr/fceux_wr.csv "data/wr/happylee-supermariobros,warped.fm2"
```
BizHawk 2.11.1 / NesHawk (mono in toolbox, Xvfb). The .fm2 is converted offline to .bk2 first —
passing a .fm2 to `--movie=` runs BizHawk's importer, which opens a "ROM required to populate
hash" dialog (invisible under Xvfb → hang):
```
python3 tools/fm2_to_bk2.py "data/wr/happylee-supermariobros,warped.fm2" data/wr/happylee-wr.bk2 --rom "roms/Super Mario Bros. (W) [!].nes"
tools/bizhawk_run.sh OUT=$PWD/data/wr/bizhawk_wr "--movie=$PWD/data/wr/happylee-wr.bk2" \
    --lua=$PWD/tools/lua/wr_dump_bizhawk.lua "$PWD/roms/Super Mario Bros. (W) [!].nes"
python3 tools/check_sync.py data/wr/bizhawk_wr.csv "data/wr/happylee-supermariobros,warped.fm2" 1
python3 tools/compare_dumps.py data/wr/fceux_wr.csv data/wr/bizhawk_wr.csv --offset 1
```
Outputs: `data/wr/fceux_wr.csv` (committed), `data/wr/fceux_wr.ram` (37 MB, 2048 bytes × 18,268
frames, frame-major; gitignored — regenerate with the command above, 18 s), `data/wr/bizhawk_wr.csv`
(committed), `*.summary`, `data/wr/happylee-wr.bk2` (committed).

## Results
**FCEUX.** The movie syncs. The joypad byte FCEUX reports after the i-th `emu.frameadvance()`
equals fm2 input line i−1 (0-based) for all 17,800 compared rows, zero mismatches → FCEUX dump
row i ↔ fm2 frame i−1. `OperMode` ($0770) first becomes 2 (`HandleAxeMetatile`, the axe touch;
`smbdis.asm` line ~12127) at row 17868 = **fm2 frame 17867 (0-based), the last frame of the
17,868-frame movie**, 19 frames after the last input (frame 17848). Timer at the axe: 317.
Movie playback mode ends at row 17870. Lag frames up to the axe: **24**.

**BizHawk / NesHawk.** Also syncs: `OperMode`==2 first at its row 17867; movie leaves PLAY at
row 17868; 24 lag frames. BizHawk rows are exactly one ahead of FCEUX rows (its lag rows are
FCEUX's minus 1; `emu.framecount()` is 1-based after the first advance) → BizHawk row i ↔ fm2
frame i. BizHawk's `joypad.get(1)` returns all-zero during movie playback, so alignment there
rests on the lag rows and game state, not on the pad column.

**Cross-emulator agreement.** With that 1-row offset, `tools/compare_dumps.py` finds FCEUX and
NesHawk **identical on every game-state column for all 18,267 common rows** (OperMode/Task,
GameEngineSubroutine, World/Level/AreaNumber, IntervalTimerControl, FrameCounter, TimerControl,
player page/X/Y/state/status, screen page, timer digits, RNG bytes $07A7/$07A8, X speed,
EnemyFrameTimer) and the lag rows coincide exactly. Only the pre-init rows differ in RAM-init
pattern (FCEUX $FF vs NesHawk $00 before the game clears RAM), which the game overwrites.

**Lag frames (FCEUX rows; fm2 frame = row−1):** 2,3,4,5,6,8,9 (boot: 7), 45 (after Start),
615, 929 (1-1 pipe in/out), 1947 (1-2 intro), 2446 (1-2 main area), 3817 (4-1, +50 after load),
6045, 6544 (4-2 intro / main), 7223 (warp zone → 8-1 load), 7774 (8-1, +50), 10816 (8-2),
12959 (8-3), 15060 (8-4), 15798, 16235, 16600, 17470 (8-4 room transitions). Pattern: one lag
frame per area load / pipe transition plus the boot frames; P0.5 should explain each from the
code (NMI overrun during loading).

**Level entry rows (FCEUX; W/L first visible):** 1-1 at 43 (OperMode→1; Start pressed on fm2
frame 41), 1-2 at 1945 (intro area, AreaNumber 1) → main area 2444 (499 rows later), 4-1 at 3767,
4-2 at 6043 → main 6542 (again +499), 8-1 at 7724, 8-2 at 10814, 8-3 at 12957, 8-4 at 15058,
axe 17868. (Spans: 1-1 1902, 1-2 1822, 4-1 2276, 4-2 1681, 8-1 3090, 8-2 2143, 8-3 2101,
8-4 2810; +43 = 17868.) P0.4 turns this into the slack table with framerule phases.

## Gotchas (encoded in wrappers/setup)
- BizHawk default `Movies.MovieEndAction = Pause` pauses the emulator when the movie ends, and
  a Lua `emu.frameadvance()` loop then blocks forever (the run was rescued by sending the Pause
  key with `xdotool` on the Xvfb display). Now set to `Finish` in config.ini / `toolbox_setup.sh`.
- BizHawk rewrites config.ini on exit (our minimal file became a 4,000-line full config; the
  patched keys survive).
- `.fm2` → `.bk2` offline conversion (`tools/fm2_to_bk2.py`) mirrors BizHawk's `Fm2Import`
  (reset/power commands, both NES ports, NesHawk sync settings) and writes the headerless
  SHA1/MD5; hash mismatches only prompt for TAStudio projects, so this is dialog-free.

## Conclusion
Acceptance met: the record movie syncs in FCEUX and BizHawk/NesHawk, per-frame state agrees
exactly between them, the ending (axe) is reached on fm2 frame 17867 (0-based) = 1-based frame
17868 = the published length. The FCEUX full-RAM dump is the ground truth for P0.4 (slack table)
and for the P1.1 fast-core differential test. Not done here (follow-ups): Mesen2 replay (needs a
Lua input driver, no .fm2 support) — useful later for P1.2 differential testing.
