# P2.5c notes — Piranha plant (Enemy_ID $0D) frame-level rules, decoded from smbdis.asm

Source: `data/disasm/smbdis.asm` (doppelganger disassembly). All line numbers below refer to that
file. Goal: enough precision for a Python reference simulation to reproduce the per-frame RAM of a
plant slot. Where the asm comment and the actual arithmetic disagree (carry-flag artefacts), the
arithmetic wins and is called out.

## 0. Constants and RAM (with defining lines)

Enemy IDs (constants): `PiranhaPlant = $0d` (606). Others referenced by the plant paths:
`Spiny` (=$12), `HammerBro` (=$05), `Podoboo` (=$0c), `Bloober` (=$07), `FlyingCheepCheep`, `Lakitu`,
`BulletBill_CannonVar`, `PowerUpObject` (=$2e), `GreenParatroopaJump` (=$0e), `Goomba` (=$06).

## 1. Spawn

### 1a. Where the plant comes from
- Plants are not in the enemy data. They are created by the **area-object** renderer when it
  processes a vertical pipe object, inside `VerticalPipe` (3843-3884). `InitPiranhaPlant` is also
  entry $0d of the enemy-data init jump table (8085), so a plant *could* be placed via enemy data,
  but vanilla levels do not do this. (If it were, `CheckpointEnemyID` 8060-8068 would first add 8 to
  `Enemy_Y_Position` and set `EnemyOffscrBitsMasked,x = 1`.)
- Decoding a large object (rows $00-$0b) in `DecodeAreaData`: second byte `& %01110000` nonzero
  selects a large object (3408-3411); `LrgObj:` stores it in `$00` (3417). If it equals `$70`
  (vertical pipe) **and** the second byte's d3 ("usage control bit") is set, `$00` is nullified to 0
  (3418-3424). `MoveAOId` shifts d6-d4 down (3429-3432), so `$00` = 7 (decoration pipe, d3 clear)
  or 0 (enterable pipe, d3 set). Both table entries (3473 index 0 and 3480 index 7) are
  `VerticalPipe`.
- **There is no "no plant" bit.** d3 only selects the pipe-top metatiles: `VerticalPipe` 3844-3848
  loads `$00`; if zero (d3 set) it uses `VerticalPipeData` rows 0-1 ($11,$10 / $15,$14), otherwise
  adds 4 to Y to use rows 2-3 ($13,$12 / $15,$14) (3837-3841). The plant spawn below does not look at
  d3 at all. (So every pipe outside 1-1 gets a plant if a slot is free.)

### 1b. Spawn condition (3850-3857), evaluated per rendered column of the pipe
```
WarpPipe: tya / pha                       ; save metatile index
  if (AreaNumber | WorldNumber) == 0: goto DrawPipe   ; world 1-1 only: never a plant (3852-3854)
  if AreaObjectLength[x] == 0: goto DrawPipe           ; second (right) column: skip (3855-3856)
  FindEmptyEnemySlot(); if carry set: goto DrawPipe    ; no free slot: skip, pipe drawn anyway (3857-3858)
```
- `AreaObjectLength` semantics: `GetPipeHeight` (3886-3894) -> `ChkLrgObjFixedLength` with Y=1
  (4278-4285): if `AreaObjectLength[x]` is negative (object just started) it is set to 1; otherwise
  left alone. Y is then reloaded from `AreaObjectLength[x]` (3893). After each column `ChkLength`
  (3350-3352) decrements it. So the first (left) column sees 1 (spawn), the second sees 0 (no spawn).
  **The plant is spawned while rendering the LEFT column of the pipe.** (`$06` = byte2 & 7 = pipe
  height, 3890-3892, used only for drawing.)
- `FindEmptyEnemySlot` (3896-3904): x = 0,1,2,3,4 in that order; the first with `Enemy_Flag[x] == 0`
  is taken (carry clear). If all five are nonzero, carry is set -> no plant. Slot 5 is never used.
  Note the search is by `Enemy_Flag` only: a slot whose flag was cleared by `KillEnemies` (3590-3600)
  still holds its old `EnemyFrameTimer`, `Enemy_CollisionBits`, `Enemy_MovingDir`, etc.

### 1c. Initial RAM (3859-3874, then `InitPiranhaPlant` 8814-8826)
- `Enemy_X_Position[x] = (CurrentColumnPos * 16) + 8` — `GetAreaObjXPosition` (4301-4307) is
  `CurrentColumnPos << 4` (CurrentColumnPos is 0..15, so 0..$f0; no overflow), then `clc; adc #$08`
  (3861-3863). `Enemy_PageLoc[x] = CurrentPageLoc + carry` (3864-3866); the carry is always 0 (max
  $f0+8 = $f8). So absolute X = page*256 + pipe_left_column*16 + 8 (sprite 16 px wide, centred on
  the 32-px-wide pipe).
- `Enemy_Y_HighPos[x] = 1`, `Enemy_Flag[x] = 1` (3867-3869).
- `Enemy_Y_Position[x] = row*16 + 32` where row = first object byte & $0f (`GetLrgObjAttrib`
  4288-4293 stores it in `$07`; `GetAreaObjYPosition` 4311-4318 does `$07<<4`, `clc`, `+32`). Rows for
  large objects are $00-$0b so Y is in $20..$d0. This is the Y of the pipe's top metatile row.
- `Enemy_ID[x] = $0d` (3872-3873).
- `InitPiranhaPlant` (8814-8826):
  - `PiranhaPlant_Y_Speed[x] ($58+x) = 1` (8815-8816)
  - `Enemy_State[x] = 0` (8817-8818; `lsr` of 1)
  - `PiranhaPlant_MoveFlag[x] ($a0+x) = 0` (8819)
  - `PiranhaPlantDownYPos[x] ($0434+x) = Enemy_Y_Position[x]` (8820-8821)
  - `PiranhaPlantUpYPos[x] ($0417+x) = Enemy_Y_Position[x] - $18` (8822-8824; `sec; sbc` — Y >= $20
    so no wrap: result in $08..$b8)
  - `Enemy_BoundBoxCtrl[x] = 9` via `SetBBox2` (8825-8826, 8874)
- **Not written at spawn** (inherit whatever the slot had): `EnemyFrameTimer[x]` (0 if the slot was
  freed by `EraseEnemyObject` 9173-9183 or by area memory init; a value left by `KillEnemies` keeps
  counting down regardless of the flag), `Enemy_MovingDir[x]`, `Enemy_CollisionBits[x]`,
  `EnemyIntervalTimer[x]`, `EnemyOffscrBitsMasked[x]` (recomputed before first use),
  `Enemy_SprAttrib[x]` (rewritten every frame).

### 1d. When (which frame) the spawn happens
- The spawn occurs inside the area parser, not the enemy loop. `ProcessAreaData` (3301) is called
  from `AreaParserCore` (3265, `RendBBuf`), which is task 3 and task 7 of the 8-task parser cycle
  (`AreaParserTasks` table 3048-3059, executed one task per frame by `AreaParserTaskHandler`
  3035-3046 with `AreaParserTaskNum` counting 8 -> 1: y=7 Core, 6 Render, 5 Render, 4 IncColumn,
  3 Core, 2 Render, 1 Render, 0 IncColumn). `IncrementColumnPos` (3062-3070) advances
  `CurrentColumnPos` (wraps 15 -> 0 and bumps `CurrentPageLoc`).
- During play, a new 8-task cycle is started by `GameEngine` (5361-5373) when `AreaParserTaskNum`
  is 0 and `ScrollThirtyTwo >= $20` (ScrollThirtyTwo is the accumulated scroll, 5404-5407, and is
  reduced by $20 when the cycle starts). At level load the whole cycle runs repeatedly in
  `AreaParserTaskControl` (1570-1580). The parser runs **after** the enemy loop within the frame
  (5311-5320 vs 5373), so the plant's first `RunNormalEnemies` is on the frame after it spawns.
- The exact spawn frame therefore depends on parser state (`CurrentPageLoc`, `CurrentColumnPos`,
  `ScrollThirtyTwo`, `AreaParserTaskNum`, `BackloadingFlag`) — that bookkeeping is not decoded in
  this note beyond the above; a sim must carry it (or take spawn frames from emulator traces).
- `EnemiesAndLoopsCore` (7763-7781) skips the enemy-data loader on frames where
  `AreaParserTaskNum & 7 == 7` (7771-7774); this does not affect plants.

## 2. Per-frame behaviour

### 2a. Frame order (what the plant code sees)
- NMI (789-805): timers are decremented **before** game logic, and `FrameCounter` is incremented
  (805) after the timer block on every unpaused frame. See section 4 for the exact rule.
- `OperModeExecutionTree` (841) -> `GameCoreRoutine` (5301): `GameRoutines` first (5305; when
  `GameEngineSubroutine == 8` this is `PlayerCtrlRoutine`, which runs `ScrollHandler` 5605 ->
  `ScreenLeft_X_Pos/PageLoc` updated 5410-5416 and `ScreenRight_* = ScreenLeft + 255` via
  `GetScreenPosition` 5462-5470, and builds the player's bounding box 5607-5609), then `GameEngine`
  (5311) if `OperMode_Task >= 3`.
- `GameEngine` (5311-5319): `ProcFireball_Bubble`, then for `ObjectOffset` x = 0..5:
  `EnemiesAndLoopsCore` (7763): if `Enemy_Flag[x] != 0` (and d7 clear) -> `RunEnemyObjectsCore`
  (9005-9015): ID < $15 -> `RunNormalEnemies` (9067-9080).
- `RunNormalEnemies` steps, in order, for a plant:
  1. `Enemy_SprAttrib[x] = 0` (9068-9069).
  2. `GetEnemyOffscreenBits` (9070 -> 14854) writes the shared `Enemy_OffscreenBits` (see 2g).
  3. `RelativeEnemyPosition` (9071 -> 14786 -> 14809-14816): `Enemy_Rel_YPos = Enemy_Y_Position[x]`;
     `Enemy_Rel_XPos = (Enemy_X_Position[x] - ScreenLeft_X_Pos) & $ff` (page ignored).
  4. `EnemyGfxHandler` (9072 -> 13614). Plant special case 13628-13634: if `PiranhaPlant_Y_Speed[x]`
     is non-negative **and** `EnemyFrameTimer[x] != 0`, the handler returns without drawing. No
     stores to `Enemy_*`/timer RAM occur anywhere in 13614-14435 (checked by search), so this step is
     graphics-only.
  5. `GetEnemyBoundBox` (9073 -> 12797): computes `EnemyOffscrBitsMasked[x]` and the hitbox (2g/2h).
  6. `EnemyToBGCollisionDet` (9074 -> 12401): **no-op for plants** — exits at 12402-12404 if state
     d5 set; exits at 12405-12406 if `(Enemy_Y_Position + $3e) & $ff < $44` (`SubtEnemyYPos`
     12652-12657; i.e. Y >= $c2 after wrap); otherwise after the Spiny/Paratroopa/HammerBro/PowerUp
     ID tests, `cpy #$07; bcs ExEBGChk` (12435-12436, 12493) exits for every ID >= 7, including $0d.
  7. `EnemiesCollision` (9075 -> 11552): only on frames with `FrameCounter` d0 = 1 (11553-11555);
     `cmp #PiranhaPlant; beq ExitECRoutine` (11563-11564) exits before anything is written. When a
     plant is the *second* enemy of some other enemy's loop it is skipped too (11580-11581). So
     plants never set/clear any `Enemy_CollisionBits` bits via this routine.
  8. `PlayerEnemyCollision` (9076 -> 11293): see 2e.
  9. If `TimerControl != 0`: skip movement (9077-9078). Else `EnemyMovementSubs` (9082) -> table
     entry $0d = `MovePiranhaPlant` (9099).
  10. `OffscreenBoundsCheck` (9080 -> 11006): section 3.

### 2b. `MovePiranhaPlant` (10577-10634), exact
```
MovePiranhaPlant:
  if Enemy_State[x] != 0:            goto PutinPipe          ; 10578-10579
  if EnemyFrameTimer[x] != 0:        goto PutinPipe          ; 10580-10581
  if PiranhaPlant_MoveFlag[x] != 0:  goto SetupToMovePPlant  ; 10582-10583
  if PiranhaPlant_Y_Speed[x] & $80:  goto ReversePlantSpeed  ; 10584-10585 (parked at TOP: no distance test)
  PlayerEnemyDiff()                                          ; 10586 (see 2c)
  if N clear (enemy at/right of player, 16-bit): goto ChkPlayerNearPipe   ; 10587
  $00 = (-$00) & $ff                                         ; 10588-10592: eor #$ff; clc; adc #$01
ChkPlayerNearPipe:
  if $00 < $21 (unsigned, 8-bit): goto PutinPipe             ; 10595-10597: stay parked at bottom
ReversePlantSpeed:
  PiranhaPlant_Y_Speed[x] = (-PiranhaPlant_Y_Speed[x]) & $ff ; 10600-10604 (1 <-> $ff)
  PiranhaPlant_MoveFlag[x] += 1                              ; 10605 (inc; 0 -> 1)
SetupToMovePPlant:
  $00 = PiranhaPlantDownYPos[x]                              ; 10608
  if PiranhaPlant_Y_Speed[x] & $80: $00 = PiranhaPlantUpYPos[x]   ; 10609-10611
RiseFallPiranhaPlant:
  if FrameCounter & 1 == 0: goto PutinPipe                   ; 10614-10616 (moves only on ODD FrameCounter)
  if TimerControl != 0:     goto PutinPipe                   ; 10617-10618 (redundant, already gated at 9077)
  Enemy_Y_Position[x] = (Enemy_Y_Position[x] + PiranhaPlant_Y_Speed[x]) & $ff   ; 10619-10622 (clc; adc)
  if Enemy_Y_Position[x] != $00: goto PutinPipe              ; 10623-10624 (exact equality test)
  PiranhaPlant_MoveFlag[x] = 0                               ; 10625-10627
  EnemyFrameTimer[x] = $40                                   ; 10628-10629
PutinPipe:
  Enemy_SprAttrib[x] = $20                                   ; 10632-10633 (graphics only)
  rts
```
- Meaning of `MoveFlag`: 0 = parked at an end of travel (either end); 1 = travelling. While
  travelling, the distance test is not evaluated (10582-10583): once it starts rising it always
  completes the rise. The speed sign says which end it is parked at / heading to: +1 = down/bottom,
  $ff = up/top. Speed is only ever +1 or $ff (never anything else unless the kill path runs, 2e).
- Parked at the **bottom** (speed +1, MoveFlag 0, timer 0): the distance test runs **every frame**
  until the player is far enough, then on that same frame it reverses and (if FrameCounter is odd)
  moves 1 px.
- Parked at the **top** (speed $ff): as soon as the timer expires it reverses unconditionally
  (10584-10585) and starts descending. Mario's position never delays the descent.
- Travel: 1 px per odd-FrameCounter frame, 24 px, so a full rise or fall takes 47 or 48 frames from
  the reversing frame depending on parity. Then `EnemyFrameTimer = 64`; the plant does nothing for
  63 following frames and resumes on the 64th (timer reads 0 in that frame's logic, see section 4).
- Cycle from spawn (assuming timer 0 and Mario far): rise 48ish -> wait 64 -> fall 48ish -> wait 64
  -> distance test.

### 2c. `PlayerEnemyDiff` (12635-12642) and the "Mario near the pipe" test
```
$00 = (Enemy_X_Position[x] - Player_X_Position) & $ff      ; sec; sbc  (12636-12639)
A   = Enemy_PageLoc[x] - Player_PageLoc - borrow           ; sbc (12640-12641); N flag returned
```
- The sign comes from the full 16-bit difference (page:X). The magnitude used is **only the low
  byte** of that difference, negated in 8 bits if the 16-bit difference was negative (10588-10592).
  The threshold is `$00 < $21` -> stay down, i.e. the plant stays in the pipe iff
  `dist8 < 33` where `dist8 = low8(enemyX16 - playerX16)` if the difference is >= 0, else
  `(256 - low8(enemyX16 - playerX16)) & $ff`.
- Consequences the sim must reproduce: a plant 256..288 px to the right of Mario (diff $0100..$0120)
  has low byte 0..$20 and **stays down**; at 289..511 px it rises; at exactly -256 (low byte 0) it
  stays down; -288..-257 (low bytes $e0..$ff -> negated $20..$01) stay down. This is reachable
  because plants are spawned ahead of the screen's right edge and are never erased to the right.
- The test uses Mario's position from this frame's `PlayerCtrlRoutine` (player moves before the
  enemy loop). Left+Right / page wrap: page is included in the sign only; no special page handling.

### 2d. Which timer gates it
- `EnemyFrameTimer[x]` ($078a+x) only. It is a **frame** timer (decremented every frame, see
  section 4). `EnemyIntervalTimer`, `IntervalTimerControl` and `StompTimer` play no role in plant
  movement. `FrameCounter` parity gates the 1-px step (10614-10616). `TimerControl` freezes
  movement (9077, 10617).

### 2e. `PlayerEnemyCollision` (11293-11314) for a plant
Runs only on frames with `FrameCounter` d0 = 0 (11294-11296; the complementary parity to
`EnemiesCollision` and to the plant's movement step). Exits (nothing written) if any of:
- `CheckPlayerVertical` (11867-11876) returns carry set: `Player_OffscreenBits >= $f0`, or
  `Player_Y_HighPos != 1`, or `Player_Y_Position >= $d0`.
- `EnemyOffscrBitsMasked[x] != 0` (11299-11300).
- `GameEngineSubroutine != 8` (11301-11303).
- `Enemy_State[x] & $20` (11304-11306).
Then `GetEnemyBoundBoxOfs` (11307 -> 11880-11889): Y = 4*x + 4 (enemy box index),
`PlayerCollisionCore` (11308 -> 12931) with X = 0 (player box at $04ac). If **no** collision:
`Enemy_CollisionBits[x] &= ~1` (11311-11313). If collision (11316-11322):
- Not a power-up; if `StarInvincibleTimer != 0` -> `ShellOrBlockDefeat` (11172-11190; "star kill",
  see below). Otherwise `HandlePECollisions` (11328-11339):
  - if `(Enemy_CollisionBits[x] & 1) | EnemyOffscrBitsMasked[x]` != 0 -> exit (already touching).
  - `Enemy_CollisionBits[x] |= 1`.
  - `cpy #PiranhaPlant; beq InjurePlayer` (11338-11339): **unconditional injury**. The stomp logic
    (`ChkForPlayerInjury` 11379-11399, including the `StompTimer` read at 11388 and the
    `Player_Y_Speed` test) is never reached, so a plant cannot be stomped and `StompTimer` is
    irrelevant to it. `EnemyStomped` (11439) would also bounce to `InjurePlayer` only for Spiny; not
    applicable.
  - `InjurePlayer` (11401-11403): if `InjuryTimer != 0` -> exit (no effect at all besides the d0
    latch above). `ForceInjury` (11405-11420): if `PlayerStatus == 0` (small) -> `KillPlayer`
    (11427-11434): `Player_X_Speed = 0`, `EventMusicQueue = 1`, `Player_Y_Speed = $fc`,
    `GameEngineSubroutine = $0b`, `Player_State = 1`, `TimerControl = $ff`, `ScrollAmount = 0`.
    Otherwise (big/fire): `PlayerStatus = 0` (A is 0 here, loaded from InjuryTimer at 11402),
    `InjuryTimer = 8` (this is an *interval* timer, offset $1e > $14: it ticks once per 21 frames),
    `Square1SoundQueue = $10`, `GetPlayerColors`, `GameEngineSubroutine = $0a`, `Player_State = 1`,
    `TimerControl = $ff`, `ScrollAmount = 0` (11408-11420).
- The d0 latch: while boxes keep overlapping on successive even frames, `HandlePECollisions` exits
  at 11329-11332 (no repeated injury). d0 is cleared only on an even frame in which the check ran
  and reported no overlap. Because spawn does not initialise `Enemy_CollisionBits`, a stale d0 = 1
  from the slot's previous occupant suppresses injury until the first non-overlapping check.
- Star kill / fireball kill (`ShellOrBlockDefeat` 11172-11190; reached from
  `CheckForPUpCollision` 11320-11322 and from the fireball path `ChkOtherEnemies` 11165-11170 —
  the fireball code does not exclude plants):
  - `lda Enemy_ID,x; cmp #PiranhaPlant; bne StnE; lda Enemy_Y_Position,x; adc #$18` (11173-11177):
    the `cmp` on an equal value leaves **carry = 1**, and there is no `clc`, so the plant's Y is
    moved down by **$19 = 25 px**, not 24 as the comment says. `Enemy_Y_Position[x] += 25` (8-bit).
  - `ChkToStunEnemies` (11178 -> 12455-12464) is entered with A = the new Y (not the ID); for any
    Y+25 >= $11 it falls to `SetStun` (12465-12492): `Enemy_State = (state & $f0) | 2`;
    `Enemy_Y_Position -= 2`; `Enemy_Y_Speed[x]` (= **`PiranhaPlant_MoveFlag`**) `= $fd` (`$ff` if
    `AreaType == 0`, water); Y=1, `PlayerEnemyDiff`, Y=2 if negative; `Enemy_MovingDir[x] = Y`;
    `Enemy_X_Speed[x]` (= **`PiranhaPlant_Y_Speed`**) `= EnemyBGCXSpdData[Y-1]` = $10 or $f0
    (12398-12399). Then back at 11179-11182: `Enemy_State = (state & $1f) | $20` -> $22; 200 points
    (`SetupFloateyNumber`), `Sfx_EnemySmack`.
  - Afterwards the slot is inert: `MovePiranhaPlant` returns at 10578-10579 (state != 0), the BG and
    player collision routines exit on d5, and nothing else moves the object (the `MoveNormalEnemy`
    defeated-enemy fall does not apply to ID $0d). The corpse stays until erased by section 3.

### 2f. `EnemyTurnAround` exclusion
`EnemyTurnAround` (11682-11685) exits for `PiranhaPlant`, so other enemies colliding with a plant
never modify it (they cannot collide anyway, see 2a step 7).

### 2g. Offscreen bits (needed for `EnemyOffscrBitsMasked` and the hitbox)
`GetEnemyOffscreenBits` (14854-14857) -> `SetOffscrBitsOffset`/`GetOffScreenBitsSet` (14863-14881)
with X = x+1 (enemy), Y = 1 (store to `Enemy_OffscreenBits` $03d1). `RunOffscrBitsSubs`
(14883-14890): result = `(Ybits << 4) | (Xbits >> 4)` where:

`GetXOffscreenBits` (14909-14934), evaluated for the right edge first (y=1) then the left (y=0),
stopping at the first nonzero result:
- Right: `$07 = (ScreenRight_X_Pos - X) & $ff`, `A = ScreenRight_PageLoc - PageLoc - borrow`.
  A < 0 (object beyond the right edge) -> `XOffscreenBitsData[$0f] = $ff`. A >= 1 -> `$00`.
  A == 0: if `$07 >= $38` -> `$00`; else index = `$07 >> 3` (0..6) -> `$7f,$3f,$1f,$0f,$07,$03,$01`
  (`DividePDiff` 14978-14989; no +8 for the right side).
- Left (only if right gave 0): `$07 = (ScreenLeft_X_Pos - X) & $ff`, `A = ScreenLeft_PageLoc -
  PageLoc - borrow`. A < 0 (object right of the left edge, the normal case) -> `$00`. A >= 1 ->
  `$ff`. A == 0 (object at or left of the left edge by 0..255 px): if `$07 >= $38` -> `$ff`; else
  index = `($07 >> 3) + 8` -> `$80,$c0,$e0,$f0,$f8,$fc,$fe,$ff`.
  After the `>> 4` in `RunOffscrBitsSubs`: right-side values become `$7,$3,$1,$0,...`, `$ff` -> `$f`,
  left-side `$8,$c,$e,$f,$f,$f,$f,$f`.
- `GetYOffscreenBits` (14949-14976): for a plant with `Enemy_Y_HighPos = 1` and `Y <= $df` the result
  is `$00`; Y in `$e0..$ff` gives `$01,$03,$07,$0f` (by `($ff-Y)>>3` = 3,2,1,0). Alive plants have
  Y <= $d0, so Ybits = 0 (a star-killed plant at Y+23 can reach $e7 -> nonzero, edge case).

`GetEnemyBoundBox` (12797-12801) -> `GetMaskedOffScrBits` (12808-12819): `$01 = (X -
ScreenLeft_X_Pos) & $ff`; `A = PageLoc - ScreenLeft_PageLoc - borrow`. If A < 0 (enemy left of the
left edge) or `A | $01 == 0` (exactly at the left edge) the mask is `$44`, otherwise `$48`.
`EnemyOffscrBitsMasked[x] = mask & Enemy_OffscreenBits`. Net effect for a plant (Ybits = 0):
- right of the left edge: mask bit is $08, and right-side X bits are $7/$3/$1/$0 -> **masked = 0**
  unless the plant is beyond the right edge ($f & $8 = $8, nonzero).
- at/left of the left edge by 0..7 px: X bits $8, mask $4 -> 0. Left by 8..55 px: $c/$e/$f -> **$4**
  (nonzero). Left by >= 56 px: $f -> $4.
- nonzero masked bits -> `MoveBoundBoxOffscreen` (12842-12851): all four hitbox bytes = $ff, and
  `PlayerEnemyCollision` exits (11299-11300).

### 2h. Hitbox (`SetupEOffsetFBBox` 12832-12838 -> `BoundingBoxCore` 12853-12889, ctrl 9)
With `rx = Enemy_Rel_XPos`, `ry = Enemy_Y_Position` (all sums 8-bit, `clc; adc`):
```
EnemyBoundingBoxCoord[4x+0] = UL_X = rx + $03
EnemyBoundingBoxCoord[4x+1] = UL_Y = ry + $0e
EnemyBoundingBoxCoord[4x+2] = DR_X = rx + $0d
EnemyBoundingBoxCoord[4x+3] = DR_Y = ry + $14
```
i.e. a 10x6 box: X from +3 to +13, Y from +14 to +20 relative to (X, Y). Then `CheckRightScreenBBox`
(12891-12929): middle = `ScreenLeft + $80` (16-bit); if the enemy's 16-bit X >= middle: if `DR_X` has
d7 clear (wrapped) -> `DR_X = $ff`, and also `UL_X = $ff` if its d7 is clear; else (left half): if
`UL_X` has d7 set and `UL_X >= $a0` -> `UL_X = 0`, and `DR_X = 0` if its d7 is set.

`PlayerCollisionCore`/`SprObjectCollisionCore` (12931-12989): compares player box (index 0..3) with
the enemy box (index 4x+4..) first horizontally then vertically, `$07` counts the two passes. Per
axis, with first = player (index y... note: Y indexes the *enemy* box, X the player box in this
call; the asm calls the Y-indexed one "first"): let (a1, a2) = enemy (UL, LR), (b1, b2) = player:
```
if a1 < b1:                    # 12940-12941 not taken
    if a1 < b2: pass (overlap)           # 12942-12943 -> SecondBoxVerticalChk:
        -> if b2 < b1: collision (wrap); elif a2 >= b1: collision; else none   # 12955-12962
    elif a1 == b2: collision             # 12944
    else: if a2 < a1: collision (wrap); elif a2 >= b1: collision; else none   # 12945-12951
else (a1 >= b1):               # FirstBoxGreater 12964
    if a1 == b1: collision
    elif a1 < b2 or a1 == b2: collision
    elif a1 < a2 or a1 == a2: none                                            # 12969-12970
    else: if a2 >= b1: collision (wrap) else none
```
Both axes must report collision (carry set at 12987). Comparisons are unsigned 8-bit.

## 3. Erase — `OffscreenBoundsCheck` (11006-11047)

Plants are **never erased for being off the right side** (11041-11042 `cpy #PiranhaPlant; beq
ExScrnBd`), only off the left. The left bound computation has carry-flag artefacts; exact
derivation (with L = `ScreenLeft_X_Pos`, Lp = `ScreenLeft_PageLoc`, T = Lp*256 + L):
```
lda ScreenLeft_X_Pos        ; 11010
ldy Enemy_ID,x / cpy #HammerBro / beq LimitB / cpy #PiranhaPlant / bne ExtendLB   ; 11011-11015
LimitB:   adc #$38          ; 11016  -- carry is SET here (the cpy that branched was an equality), so A = L + $39
ExtendLB: sbc #$48          ; 11017  -- carry-in = carry-out of the adc
sta $01 ; lda ScreenLeft_PageLoc ; sbc #$00 ; sta $00                               ; 11018-11021
```
- Plant (and Hammer Bro): if `L + $39 < 256` (L <= $c6): bound16 = T - 16. If `L >= $c7` (the adc
  carried): bound16 = T - 271. (Working: low = L+$39-256 with carry 1 -> low - $48 = L - $0f - 256.)
  The sbc on the page propagates the borrow, so `$00:$01` is a proper 16-bit value (for page >= 1).
- For comparison, other enemies arrive at `ExtendLB` with carry from `cpy #PiranhaPlant` (not
  equal): IDs > $0d get L - 72, IDs < $0d get L - 73 (not 56/72 as the comments say).
- Erase test (11029-11033): `cmp $01` on X, then `sbc $00` on the page; if the 8-bit result is
  negative -> `EraseEnemyObject`. Equivalently, for pages < $80: **erase iff enemyX16 < bound16**,
  i.e. the plant is erased once its X is more than 16 px left of the screen's left edge (its 16-px
  sprite is fully off), except during the window L in $c7..$ff where the bound is 271 px to the left.
- Right bound (11022-11028) for completeness: `$03:$02 = ScreenRight16 + $48 + Cp` where Cp is the
  carry out of the page sbc at 11020 (1 unless Lp borrowed below 0). Enemy >= that bound -> for
  plants: exit without erasing.
- `EraseEnemyObject` (9173-9183) zeroes: `Enemy_Flag`, `Enemy_ID`, `Enemy_State`,
  `FloateyNum_Control`, `EnemyIntervalTimer`, `ShellChainCounter`, `Enemy_SprAttrib`,
  `EnemyFrameTimer`. It does **not** clear X/Y, speeds, `Enemy_CollisionBits`, `Enemy_MovingDir`,
  `PiranhaPlant*YPos`.
- Other removal: `ScrollLockObject_Warp` (3565-3579), the warp-zone area object, calls
  `KillEnemies` with `PiranhaPlant` (3578-3579): `KillEnemies` (3590-3600) sets `Enemy_Flag = 0`
  for every slot x = 4..0 whose `Enemy_ID == $0d` — only the flag; timers and everything else stay.
  Relevant to the 1-2 / 4-2 warp zones used by the route.

## 4. Timers — exact decrement rule (NMI, 785-805)

```
lda TimerControl ; beq DecTimers        ; 795-796: if TimerControl == 0 -> decrement timers
dec TimerControl ; bne NoDecTimers      ; 797-798: else decrement it; if it became 0, timers ALSO tick this frame
DecTimers:  ldx #$14                    ; 789  (frame timers: Timers+$00..Timers+$14 = $0780..$0794)
  dec IntervalTimerControl ; bpl DecTimersLoop   ; 790-791
  lda #$14 ; sta IntervalTimerControl ; ldx #$23   ; 792-794 (wrap: also do interval timers $0795..$07a3)
DecTimersLoop: lda Timers,x ; beq SkipExpTimer ; dec Timers,x   ; 795-797 (8-bit, stops at 0)
SkipExpTimer:  dex ; bpl DecTimersLoop
NoDecTimers:   inc FrameCounter         ; 805 — always (unless paused, 786-788 / PauseSkip)
```
- `EnemyFrameTimer[x]` = `Timers + $0a + x` ($078a..$078e for x = 0..4): a **frame timer**,
  decremented by 1 every frame when nonzero, as long as `TimerControl == 0` (or just reached 0).
  Set to $40 by the plant (10628-10629) -> the plant idles on the following 63 frames and resumes
  on the 64th frame after the set (the NMI of that frame takes it to 0 before the logic runs).
- `IntervalTimerControl` ($077f) counts 20,19,...,0 then wraps: on the frame where it would go
  below 0 it is reset to $14 and the interval timers (`Timers+$15..$23`, including
  `EnemyIntervalTimer` $0796+x and `InjuryTimer` $079e) decrement. Period 21 frames. Plants do not
  read any interval timer; only the injury invincibility (`InjuryTimer = 8`, ~8*21 frames) does.
- `TimerControl` is set to $ff by `ForceInjury`/`KillPlayer` (11419-11420 via `SetKRout`). While
  nonzero: no timer decrements (above) and `RunNormalEnemies` skips movement (9077-9078). Plant
  state is frozen exactly, including `EnemyFrameTimer`.
- `FrameCounter` is incremented in the NMI *before* the game logic, so "odd `FrameCounter`" in
  `MovePiranhaPlant` refers to the post-increment value of the current frame. The movement step
  (d0 = 1) and the player-collision check (d0 = 0) therefore happen on alternating frames.

## 5. Minimal Python-style model of one frame for slot x (derived from the above)

```
# NMI part (once per frame, before any enemy logic):
if TimerControl == 0 or (TimerControl := TimerControl - 1) == 0:
    tick frame timers (EnemyFrameTimer[x] -= 1 if > 0); handle IntervalTimerControl wrap
FrameCounter = (FrameCounter + 1) & 0xff
# ... PlayerCtrlRoutine: Mario moves, ScreenLeft updated, player box built ...
# RunNormalEnemies for plant x (only if Enemy_Flag[x]):
relx = (X - ScreenLeft_X) & 0xff
compute Enemy_OffscreenBits, EnemyOffscrBitsMasked (2g); box = 4*[0xff] if masked else (relx+3, Y+14, relx+13, Y+20) with CheckRightScreenBBox fixups
if FrameCounter & 1 == 0: PlayerEnemyCollision (2e)
if TimerControl == 0: MovePiranhaPlant (2b)
OffscreenBoundsCheck (3)
```

## 6. Things checked but left open / caveats
- Spawn frame: depends on area-parser scheduling (1d); not fully decoded here.
- `Enemy_CollisionBits[x]` and `EnemyFrameTimer[x]` at spawn are inherited from the slot (1c);
  a sim should track slot history or assume 0 (true when the slot came from `EraseEnemyObject` or
  area init).
- The `cmp #$09 .. Demote` block in `ChkToStunEnemies` (12455-12464) tests A = Y+25 rather than
  the ID; for a plant (Y >= $20) A >= $39 so it always reaches `SetStun` and never demotes. Stated
  here because the asm comment at 12460-12463 is about exactly this quirk.
- Sprite-side effects (`Enemy_SprAttrib`, the draw skip at 13628-13634, `FloateyPart` at
  1317-1318) are graphics-only and do not feed back into the RAM used by logic.
