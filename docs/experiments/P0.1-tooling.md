# P0.1 — Emulator tooling on the Linux box (2026-08-21)

## Goal / acceptance
FCEUX (with Lua), BizHawk and Mesen2 each launch headless/scripted on the Linux box; versions
and machine specs recorded in `docs/facts.md`.

## Machine
`laptop`: Fedora Linux 43 (Workstation), kernel 6.18.6-200.fc43.x86_64, 13th Gen Intel Core
i5-1335U (10 cores = 2 P-cores w/ HT + 8 E-cores → 12 threads, max 4.6 GHz, 12 MiB L3),
15 GiB RAM + 8 GiB swap, NVMe, 217 GB free on /home. gcc 15.2.1, Python 3.14.2, luajit present;
no cmake/clang/rust on the host. Wayland session (DISPLAY=:0, WAYLAND_DISPLAY=wayland-0).

## Constraint and the chosen layout
`sudo` on the host needs a password, so host `dnf install` cannot run unattended. Layout used:
- **Rootless `toolbox` container `smb1`** (fedora-toolbox:43 image; passwordless sudo inside;
  shares $HOME, /tmp, the display, the network). Holds **FCEUX 2.6.6** (RPM Fusion
  `fceux-2.6.6-11.fc43`, Qt5/SDL2 build linked to `liblua-5.1`), **Xvfb 21.1.24**,
  **mono 6.12.0.199** + libgdiplus 6.1 (for BizHawk), cmake 3.31.11, clang 21.1.8, gdb 17.2,
  strace 7.2, ImageMagick/xwd/xdotool/xwininfo (to screenshot/drive the hidden display).
- **Mesen 2.1.1** (`~/opt/mesen2/Mesen`, self-contained .NET single-file build, sha256
  `7a9947…1ce9`) runs **natively on the host**.
- **BizHawk 2.11.1** (`~/opt/bizhawk/BizHawk-2.11.1-linux-x64/`, sha256 `38c9c1…93f`) runs via
  `EmuHawkMono.sh` **inside the container** (mono). NES core pinned to NesHawk in `config.ini`.
- Everything is reproduced by `tools/toolbox_setup.sh` (idempotent). Wrappers:
  `tools/fceux_run.sh`, `tools/mesen2_run.sh`, `tools/bizhawk_run.sh`.
- Native alternative if Matt ever runs it on the host (then `tools/fceux_run.sh` uses the host
  binary automatically):
  `sudo dnf install -y fceux xorg-x11-server-Xvfb mono-core mono-devel libgdiplus lsb_release cmake clang gdb strace`

## Gotchas found (each cost real time; all encoded in the wrappers/setup script)
1. **Mesen2 first-run wizard**: if `~/.config/Mesen2/settings.json` is missing, `Program.Main`
   starts the Avalonia GUI *before* looking at `--testrunner` — a window opens on the real
   desktop and the process hangs forever headless. Fix: write a settings.json first.
2. **Mesen2 `std::bad_cast` abort** on Fedora 43 (ICU 77): the .NET runtime aborts at startup.
   Fix: `DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1`.
3. **Mesen2 `emu.log` never reaches stdout** even with `--enableStdout` (only core messages do).
   Scripts must write files; Lua `io` is gated by `Debug.ScriptWindow.AllowIoOsAccess=true`
   in settings.json. `ScriptTimeout` (per-callback seconds, default 1) raised to 3600.
4. **Mesen2 testrunner syntax**: `Mesen --testrunner [--timeout=S] script.lua rom.nes`; the
   script ends with `emu.stop(code)` → process exit code; 255 = timed out (default 100 s).
5. **FCEUX runs at real-time 60 fps by default** under Lua; call `emu.speedmode("nothrottle")`.
   `emu.exit()` segfaults on shutdown (exit 139) *after* the script has finished — harmless,
   but exit codes are meaningless; rely on output files.
6. **`toolbox run` does not forward the caller's environment** — wrappers take leading
   `VAR=VAL` arguments and pass them via `env`.
7. **BizHawk modal dialogs are invisible under Xvfb** and block forever. Two were hit:
   "Couldn't initialize sound device" (OpenAL; fixed by `"SoundOutputMethod": "Dummy"`), then
   "Mismatched version in config file" (fixed by `"LastWrittenFrom": "2.11.1"`). Diagnosis
   recipe: run Xvfb on :99, launch EmuHawk on it, `xwininfo -root -tree`, `import -window root`.
8. `pkill -f EmuHawk.exe` from the agent shell kills the agent's own shell (its command line
   contains the pattern). Use `pkill -x mono` / `pkill -x Xvfb` / `pkill -x Mesen`.

## Smoke tests (all three pass; scripts in `tools/lua/smoke_*.lua`)
Each script runs 300 frames from power-on (no input) and logs `FrameCounter` ($09) and
`OperMode` ($0770) every 60 frames. Exact commands:
```
tools/mesen2_run.sh  tools/lua/smoke_mesen2.lua  "roms/Super Mario Bros. (W) [!].nes" 20   # → ~/opt/mesen2/smoke_out.txt, exit 0
tools/fceux_run.sh   --loadlua tools/lua/smoke_fceux.lua  "roms/Super Mario Bros. (W) [!].nes"  # → ~/opt/fceux_smoke_out.txt (exit 139 expected)
tools/bizhawk_run.sh --lua=$PWD/tools/lua/smoke_bizhawk.lua "roms/Super Mario Bros. (W) [!].nes" # → ~/opt/bizhawk_smoke_out.txt, exit 0
```
Observed at script iteration 60 / 120 / 180 / 240 / 300 (power-on, no input):

| Emulator / core | `emu.framecount()` at i=60 | FrameCounter $09 at i=60…300 | lag frames by i=300 |
|---|---|---|---|
| FCEUX 2.6.6 | 59 | 51, 111, 171, 231, 35 | 7 |
| Mesen 2.1.1 | (endFrame callback count 60) | 53, 113, 173, 233, 37 | n/a |
| BizHawk NesHawk | 60 | 53, 113, 173, 233, 37 | 6 |
| BizHawk QuickNes | 60 | 54, 114, 174, 234, 38 | 5 |

FrameCounter advances by exactly 1 per emulated frame in all four once the game is running; the
offsets differ by 1–3 frames because of boot-time lag/alignment conventions (FCEUX's counter
is 0-based at the first `frameadvance`, BizHawk's 1-based; the number of boot lag frames
differs). **P0.3 must establish the fm2-frame ↔ emulator-frame alignment explicitly** rather than
assume it; these numbers are the first data point.
